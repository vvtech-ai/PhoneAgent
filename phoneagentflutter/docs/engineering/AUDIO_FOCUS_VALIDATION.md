# 跨模块音频占用：实现与集中验收

## 当前交付范围

2026-09-18，普通单路/批量录音、翻译历史录音、克隆试听已接同一个进程级共享管理器。此前三者分别创建播放器，普通回执仅在会话内部互斥。新架构不复制 v65 巨型页面，而在设备播放边界复用纯 Dart 协调。

**本批不等于全部音频完成**：SDK 身份采集已在下述接续批接入；语音按住说话/ASR/TTS、单路监听、LiveKit/AppAudio 实时翻译尚未接入该管理器。平台音频焦点/AVAudioSession、中断与路由依然需要真机验证；Dart 占用不是 OS 焦点成功的证明。

## SDK采集接续（2026-09-18）

- `voice_clone/data/focused_identity_capture_port.dart`包裹正式DeviceIdentityCapturePort，由`clone_flow_providers.dart`注入同一focus。prepare不申请媒体租约；capture前等待旧可中断播放停止，持有不可被试听抢占的租约。后台PASS判定及生成/扣费契约不变。
- 新通道`waitForRelease(session)`区分业务取消与设备释放确认。Android保留release失败的facade，abort失败允许重试；准备未结束时不提前解锁。iOS取消先抛弃业务结果，但直到供应商完成和自己的容器关闭才确认释放，并发dismiss共用完成队列。没有调用供应商私有API。
- 共享装饰器在成功、失败、账号变化/离页时等待原生收尾，再归还原租约；较晚释放/较旧结果不能覆盖新账号。停止超时继续保持占用，不能凭超时强制解锁。
- **已知限制**：iOS供应商若取消后永不回调，采集与其他共享播放器都会保持受保护占用；这不是“已释放”。普通文字页面仍可使用。必须真机观察相机/麦克风指示器并确认供应商公开取消能力，不能用Dart测试证明实际硬件已释放。
- 8108增加合成SDK按钮；与正式代码共用装饰器，仅native端口使用内存Completer，不加载SDK、不采集身份。浏览器已验证普通播放→采集暂停旧播放→拒绝克隆抢占→取消仍等待→模拟SDK释放→恢复克隆试听→停止。
- 新增18项（共享采集9、通道5、页面4），全量1775项通过；analyze无问题；815个Dart文件格式检查无修改。Web/Android Debug/Mac iOS Debug无签名构建通过；实际SDK生命周期未运行。

人工追加：两端先试听再进入已授权SDK采集，确认旧声音停止；完成/取消后观察相机和麦克风指示器关闭，再重新试听；iOS重点检查取消后迟到回调与再次采集busy。采集中退出账号/销毁页不得继续生成或串账号。记录操作时间、平台/设备和错误类别，不记录身份、metaInfo、certifyId、原始SDK响应。真实测试需要合法测试身份与明确采集授权，本轮未执行。

## 实现位置与边界

| 文件 | 职责 |
| --- | --- |
| `core/audio/audio_playback_focus.dart` | 串行申请、等待停止、最后请求生效、超时保留旧占用、保护型租约和全部停止 |
| `core/audio/audio_resource_coordinator.dart` | 现有唯一租约事实、旧租约不能释放新占用 |
| `app/audio_focus_providers.dart` | 同一进程实例；账号变化停止旧播放而非创建新管理器绕过旧硬件 |
| `translation_history/data/focused_recording_player.dart` | 普通/翻译播放装饰器；预加载不占用，play/resume申请，暂停/结束/失败实际停止后释放 |
| `voice_clone/data/focused_clone_preview_player.dart` | 试听装饰器；播放完成等待原生清理，失败尝试实际停止，不假报设备空闲 |
| 三个生产 provider | `call_recording_providers.dart`、`recording_providers.dart`、`clone_flow_providers.dart` 注入同一 focus，保留各自账号/离页判断 |
| 两个 plugin player | 释放失败保留底层句柄，供明确重试；克隆也禁用可能含私有路径的插件日志 |

新用户播放请求先停止可中断旧播放；旧停止成功才授予新租约。超时5秒不等于设备已停止：保留原租约，后续重试复用仍在进行的停止，不重复并发停止。停止报错可再次显式重试。旧播放不会因为新播放结束而自动恢复。

普通回执内部原管理器仍控制按点击加载和结果卡生命周期；全局装饰器负责真正播放边界，二者职责不同。翻译历史仍预下载、不自动播放。保存不获得音频租约、不变更原有下载和导出顺序。被切换暂停通过正式事件回到原控制器/录音卡，不由页面直接操纵设备。

## Web 验证

入口：开发者页“打开跨模块音频演练（MOCK）”，或运行 `flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8108 -t tool/previews/audio_focus_preview.dart`。

演练复用正式协调器、两类播放装饰器、录音控制器与录音卡；仅底层录音源/播放器/试听替换成内存计时事件。无 Web Audio、文件、麦克风、真实账号或服务请求，保存按钮返回取消。可演练普通→翻译→克隆→普通、停止全部、停止失败后解除故障重试。

浏览器8108已确认普通playing→翻译playing且普通paused→克隆试听且两类录音paused→停止全部。320/390/430宽Widget回归另外覆盖回到普通、失败不重叠与显式重试。没有把页面计时当真实声音证据。

## 集中人工验收（尚未执行）

1. Android/iOS分别打开有授权的普通录音与翻译录音，点击播放/暂停/继续/结束后重播，核对声音与卡片状态一致，预加载没有声音。
2. 普通→翻译→克隆试听→普通连续切换，确保不同时出声，旧播放保持暂停且不自动恢复；克隆结束后允许其他播放。
3. 快速连点、加载中返回、退出账号再登录，等待旧请求返回，不能迟到播放或串到新账号。
4. 播放中切后台/锁屏/拔耳机/接系统电话/蓝牙变更，检查原有页面生命周期及插件OS中断回调；不能仅凭Dart租约测试宣称路由正确。
5. 平台停止/释放异常：页面显示原有清洗后的失败信息，新播放不与旧播放重叠；记录错误类别和操作时间，不复制私有URL/录音路径/音频内容。
6. SDK按新增步骤验收；后续接通ASR/TTS/监听/实时翻译时，逐一加正式focus接线和上述交叉验收；未接通前不能勾选 `2.10b2b` 全局媒体验收。
