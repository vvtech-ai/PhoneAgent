# 身份删除后本地处理：重试与集中验收

2026-09-18；identity-profile-core 2.10。这里只补完已确认的失败恢复交互，不新增身份字段，不改变后端删除语义，不代表全部迁移完成。

## 问题和实现

原有 `IdentityController.delete` 在服务端 DELETE 成功后执行跳过偏好保存与认证录音清理；本地失败只显示错误。`IdentityPage` 仅为资料加载失败提供重试，用户无法恢复本地失败。重复 DELETE 也不能用于重试本地处理。

正式链路：`IdentityRoute` 确认删除 → `IdentityController.delete` → 原 Repository DELETE → 每次删除创建独立 `IdentityDeletionCleanup` → 失效模型/音色缓存、保存跳过偏好、清理原录音。服务端成功始终保留空身份；本地失败显示“重试本地处理”，成功后清除错误和待处理状态。处理期间互斥，待处理时当前页面暂不进入重新填写，返回仍可用。

- 共享 Dart `IdentityDeletionCleanup` 并行尝试两个本地步骤，记住已成功步骤。显式重试只做失败步骤；不再次 DELETE，不重复已成功持久化或模型刷新。
- `CertifiedRecordingRepository.prepareClear` 捕获删除时已排队的写入边界；同 slot 实例共享串行队列和成功写入序号。删除之前排队的保存先完成再清理；删除之后成功保存的录音属于新流程，旧重试不得清除，即使字节相同。后续保存失败则不算替换，旧录音仍应清理。
- 任务绑定创建时的录音 Repository，账号变化/关闭沿既有 isCurrent 检查拒绝旧任务；重试时不会重新查找新账号仓库。没有原生接口、后台协议或录音格式变更。
- 待处理任务是页面控制器内存状态，不持久化；离开后不自动重试，也不提供崩溃后任务恢复。本批不声称跨进程清理恢复已经实现。真实系统文件/钥匙串行为仍集中验收。

## 集中人工步骤

前提：取得阶段包安装授权，使用获准删除的测试身份和测试录音；不得拿真实业务资料制造失败。故障注入只在专用测试构建启用，正式页面无隐藏破坏开关。

1. 正常删除：确认后空身份、模型音色刷新、旧本机录音不可复用；未确认/取消不发送 DELETE。
2. 仅跳过偏好写入失败：服务端和录音清理成功，专用按钮重试偏好；后台 DELETE 总数必须为 1，录音清理不重复。
3. 仅录音清理失败：已保存跳过状态保留；解除存储故障后点击重试，错误消失、录音清空，不重新请求身份删除。
4. 保存录音尚未完成时删除：本槽串行等待旧保存后清理；删除后又有新的成功录音保存，旧重试不能删除新文件。若新保存失败，旧文件仍是应清理目标。
5. 清理等待时返回或切账号：不更新已销毁页面，不在新账号执行清理，无自动删除/重复收费/认证。离页后不声称本地失败已解决，跨进程重试不在本批范围。

只核对测试环境时间窗、脱敏错误类型与既有关联 ID；不要记录身份正文、音频、receipt 或凭据。失败标准：重复 DELETE、清除新账号/新录音、把本地失败报为后台删除失败、无重试入口或虚报本地成功。
