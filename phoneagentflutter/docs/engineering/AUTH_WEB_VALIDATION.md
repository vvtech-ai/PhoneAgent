# 登录与邀请码 Web 验收（2026-09-16）

## 本批完成范围

直接运行正式 `PhoneAgentApp → AuthRoute → AuthPage → AuthController/SessionController`，只替换短信/登录网关和会话存储。登录、邀请码两页的基础布局不改，设计来源仍为固定 `0cd58de9`，本批重新查看缓存 login 截图确认不是初始化遮挡页。

本批补齐 Web 表单交互验收，不代表所有迁移页面完成，也不把合成邀请码通过当成真实账号满足邀请码条件。真实 Android/Web 会话沿用既有验证；本批没有真实短信、真实登录或账号写入。

## 可重复入口和边界

```powershell
E:/dev/flutter/bin/flutter.bat run -d web-server --web-hostname 127.0.0.1 --web-port 8092 -t tool/previews/auth_preview.dart
```

打开 `http://127.0.0.1:8092`。页面顶部常驻 MOCK 标识；只在 debug 模式运行。使用合成号码 `13800000000`、验证码 `1234`、邀请码 `DEMO`；任意其他四位数字验证码/其他邀请码用于拒绝分支。

- `tool/previews/auth_scenario.dart`：只实现内存端口，无 HTTP/安全存储/磁盘操作。四种场景为邀请码、直接登录、首次保存失败、首次恢复失败。
- `tool/previews/auth_preview.dart`：替换外部 provider、强制无 API 配置；正式页面和控制器不复制。场景重置销毁旧 provider scope；刷新页面清空合成会话。
- 合成首页只作为真实登录路由的落点，显示“MOCK 登录成功”，不用于其他业务验收。首页与模型读取也被替换，不拉取线上数据。
- 普通 `lib/main.dart` 不导入此入口。现有 `localhost:8080`、Android 安全存储和用户登录态均不读取/清除；没有为了截图重新获取验证码。
- 预览顶栏占用高度，截图不能用于原设计的整页像素差分；只对正式表单的可读性/交互取证。未声称所有字体、键盘与原生系统差异已验收。

## 后续集中人工验收

1. Android/iOS 真机用已登录态优先验证首页；只有实际需要重新登录时才请求短信。不要用上述合成账号信息登录真实环境。
2. 真机退出/登录前先确认测试范围；打开系统键盘，检查手机号→验证码焦点、输入可见、收键盘、邀请码返回。预期无底部空白/溢出，系统字体和安全区可有平台差异。
3. iOS 首次真实登录及跨进程安全存储仍待验证；不能由内存 SessionStore 回归替代。
4. 真实后端仅在满足邀请码条件时测试该分支，不制造生产账号条件；已自动覆盖 challenge 存在时不重复提交 SMS code。
5. 故障证据只记录失败阶段、接口错误分类和脱敏关联信息，不记录短信内容、accessToken、loginChallenge 或完整手机号。禁止验证码被重复消费、保存重试再次发送短信、旧邀请码请求返回后自动登录。

本批未改 `lib/`、Android/iOS 配置或插件，因此没有重装双端；不把以往设备安装记成本批新增真机结果。设备当前版本与其他未完成模块以总验收清单为准。
