# 完整App文档与OCR连续验证

2026-09-20；基点fab48ac加本批。仅隔离MOCK接线和测试，正式lib/原生/接口不变；不是相册、识别质量或后台收件验收。

## 在Web查看

打开[8122验收目录](http://127.0.0.1:8122/)，进入第一项完整App→订餐厅→添加内容：

1. **文档**→选择文件：只返回内置合成任务.docx、合成名单.xlsx，按正式controller解析成功后自动发送，无额外确认步骤。
2. 关闭任务对话→任务列表→MOCK · 文档资料：恢复已上传文档和待选候选，不把序列化JSON显示在列表/消息中。
3. 选候选后添加内容→**相册**：只读取打包的合成名片图片，走正式OCR controller，展示只读图片/提取文字；选图本身不发Agent命令。
4. 切文字提交“整理图片，不要拨号”→关闭→任务列表恢复：文档、图片及续聊同属原session；恢复后可继续发文字。

顶部常驻MOCK。正式文档说明沿用“上传至当前环境”，在本入口实际没有上传；外部端口全部替换，不打开系统选择器、不读取私人文件。独立“文档交互演练”仍只展示弹层，不提交对话，不能和本链路混淆。

## 实现边界

- [ShellAttachmentPorts](../../tool/previews/shell_attachment_ports.dart)替换文档factory及OCR选择/识别/存储；复用既有合成数据与正式DocumentImportController/OcrSessionController。
- [ShellConversationPorts](../../tool/previews/shell_conversation_ports.dart)同时提供Agent、任务、历史，保存文档inputKind；OCR_IMAGE_COMMITTED进入同一有序ledger，图片严格按session/id查找。图片单独上传也创建合成任务；恢复不重复上传。
- provider随合成登录代次重建，关闭拒绝晚到提交并释放图片；不是跨进程持久化或真实后端。未模拟呼叫或任务完成，任务仍未完成。
- OCR结果遵循现有只读/长文字展开收起，不新增编辑、确认或执行按钮。
