## Flutter 缺陷及修复边界

1. apology binding 回显复用原 prompt.commandId；公共 merge 将同 command 的 user 放在 assistant 前。回显使用独立本地动作 commandId，仍与消息 id 关联；不改变普通用户轮次的排序。
2. 文本选择绕过 binding.choose，缺少回显。将被识别为选项的输入统一转到 binding.choose；保留普通任务输入的 source/document 续接。
3. Checking 通过 _show 进入历史消息。改为独立 checking 通知，清操作权并保存 pending 恢复快照，不插入消息或播报。
4. 道歉配置 opening 与专用 Consent 重复。entry 展示层按原生入口分支跳过道歉配置 opening；已显示的 Consent 保留，普通配置 opening 保留。
5. 仅本地道歉 options 提问使用独立助手气泡，选项容器只含选项；普通 options 保留卡内标题。道歉选择索引保存在 ConversationMessage 本地快照，组件重建仍保留高亮和 disabled，不进入 wire 或 durable ledger。
6. 公共 merge 原先从 durable 开始，未匹配的本地交互被追加到后续事实末尾；改为在临时列表寻找后续 command 对应的 durable 事实，将本地交互插在它之前，不重排账本事实。不限定道歉 Skill；覆盖有/无上一轮事实两种顺序。
