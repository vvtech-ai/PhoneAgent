# 禅道 23811：结果等待与终卡交互

## 问题与证据

用户反馈：多路通话被本机全屏来电遮挡后，原会话的状态和终卡可能未及时更新；进一步核对时发现客户端还可能显示黄色“结果确认中／结果未确认”结果卡。源码回放确认两处客户端边界：单路只有物理完成或已提交 `callResult.status=COMPLETED`，却没有可信业务结论时，旧展示路径仍可能画出黄色结果卡；多路五分钟观察截止仍未取得已提交结果时，本地 `UNCLEAR` 快照会被组件画成“执行结果／结果回传”区域。单路旧回执准入还可能仅凭已提交标记结束结果观察。

旧 test 现场已有后端终态证据：10:22:27.117 写入 `ASSISTANT_TURN_COMMITTED` 序号 27，批量回执为 `PENDING / executionStatus=EXECUTION_ERROR`；10:23:16 同批进度读取返回 `resultSequence=27`，timeline 也同步到 27。因此这一次不能描述为“服务端始终没有终态”。旧客户端诊断没有该批次身份或响应体，不能仅凭 HTTP 200 证明页面已解析并显示红色终卡；源码与合成回放表明旧进度卡可能覆盖已提交回执。本轮本地修复尚未在 test 真机复测。

## 验收口径

1. 单路仅有物理结束、`call_finished` 或已提交 `COMPLETED`，没有同身份可信业务报告或合法的语义 `agentOutcome`，且没有明确技术异常时，继续显示结果整理／待核实反馈，不生成黄色、绿色或红色结果卡；`PENDING`、未知 outcome 和单独的业务 `resultCode` 不能结束等待。明确技术异常沿用红色异常反馈，但不据此宣称业务已裁决。
2. 收到可信结果后原位结束等待：已确认完成显示绿色终卡；可信失败、`UNCLEAR` 或 `EXECUTION_ERROR` 显示红色未完成／执行异常终卡。保留通话、账务与转写的已知事实。
3. 多路五分钟观察截止仍没有已提交终态时，停止自动轮询，原临时进度显示“结果尚未确认”，不出现“执行结果／结果回传”终卡区域；保留批次身份、已知逐路事实和恢复补查入口。迟到的同批可信回执可原位替换。
4. 超时不强行推断业务成功或失败，也不自动重拨。是否能取得服务端终态仍以实际服务端事实和同身份读取为准。

本轮范围为 Flutter 本地行为修复和定向回放；不改后端接口、积分结算或服务端终态生成规则。
