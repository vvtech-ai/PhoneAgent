## 旧现场证据

test 后端日志在 10:22:27.117 记录批量 `ASSISTANT_TURN_COMMITTED` 序号 27；运行代码对应回执为 `status=PENDING / executionStatus=EXECUTION_ERROR`。10:23:16.132 同批进度读取返回 `resultSequence=27 / resultPresent=true`，10:23:16.287 timeline 同步到 27。服务端红色执行异常终态**已经提交**，不能把旧现场写成始终拿不到服务端结果。旧客户端诊断没有该批次身份或响应体，不能直接证明客户端解析、展示了这份回执；旧进度卡覆盖已提交结果的缺口由源码与本地合成回放支持。

## 定向用例

| 场景 | 预期 |
| --- | --- |
| Android/iOS 单路物理完成，或账本提交 `COMPLETED`，无业务报告且无明确技术异常 | 继续显示整理／待核实文字，不画结果卡 |
| 明确技术异常字段到达，业务结果仍未裁决 | 沿用红色异常反馈；结果观察不把它误记为业务成功 |
| 物理回执或已提交结果只有 `resultCode` | 不因此结束观察或推断成功、失败 |
| `agentOutcome=PENDING/UNKNOWN`，即使有成功 `resultCode` | 当前页不画终卡，结果同步器继续补查 |
| 同身份可信 `agentOutcome`、`UNCLEAR` 或 `EXECUTION_ERROR` 到达 | 原位显示对应绿色完成或红色未完成／执行异常终卡 |
| 多路含进行中或已失败路，五分钟仍无已提交批量结果 | 停轮询，保留进度和逐路事实，显示“结果尚未确认”；不画“执行结果／结果回传” |
| 后续同批次可信结果到达 | 原位替换临时进度；不重拨、不跨身份覆盖 |
