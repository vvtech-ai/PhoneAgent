# 修复设计

日志追加设计见本 change 的“用户追加日志授权”。原生仅以 FlutterError.details 返回固定结构，Dart 白名单解析并经现有 journal 导出；TTS 可选 mediaRequestId 查询参数在现有签名之前加入，不打印 URL。旧端/旧日志兼容，回滚只撤销本轮字段和埋点增量。

检索方法：App 导出日志中 operation=voiceMedia、media.component=taskTts 的 media.requestId，对应 Java event=task_tts_stage 的 mediaRequestId；Java 同行提供当前握手 traceId，可继续关联握手日志。客户端 attempt 表示连接/重连序号，后台 attempt 表示该连接内合成序号，跨端以请求 UUID 关联。App 的共享 traceId 将同一回复的 PCM 与各段 TTS 关联。

PCM 的 native.phase 区分类别设置、激活、路由、引擎启动等步骤；native.domain 只保留 osStatus/audioSession/cocoa/other，code 为数值，appState 为 UIKit 原始状态 0/1/2，-1 表示未知。route 只保留路由类别，不包含设备名；启动异常快照在清理之前采集，停止失败快照在释放失败时采集。开始、停止及首次实际播放完成记录耗时，不逐帧打印。

见 [OpenSpec 设计](../../../../openspec/changes/repair-23731-23737-23739-23748-voice-parity/design.md)。

号码转换使用纯函数；思考展示按 command 隔离且不进入播报或 ledger；原生错误使用诊断枚举白名单。不改接口、外呼授权或计费。不覆盖既有单呼、录音等未提交改动。回滚仅撤销本批增量。

追加取消分类修复：当前 iOS PcmOutputChannel.release 调用 cancelPending，并以 output_interrupted 结束待播请求。DevicePcmOutput 只有在本实例已调用 stop、操作不是 stop 本身且原生错误明确为 output_interrupted 时，才转换为 output_cancelled。其余错误沿用原分类，不把 output_play_failed 或失败的 stop 变成成功。只修改 Dart 适配层，不改变 MethodChannel 接口或原生实现。回滚时仅撤销该映射及直接对应的新增回归用例，保留诊断分类和其他会话改动。
