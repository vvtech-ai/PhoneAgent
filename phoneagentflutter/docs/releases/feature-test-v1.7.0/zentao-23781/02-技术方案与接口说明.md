# 技术方案与接口说明

## 实现方案

在 `BatchReceiptProjector` 处理同一批 Timeline facts 时，复用 `CallReceiptProjector` 输出的结构化回执。以 `(sessionId, callAttemptId)` 为严格键建立账单候选；批次项已有 `billingSummaries` 时保留原值，只有空列表且精确命中唯一回执账单时才补入。

该方案不新增接口和依赖，不读取积分流水，不根据积分差额、通话时长、模型价或挂断状态造数。没有同尝试事实时维持当前无账单显示。

## 影响和兼容

- 只影响 Flutter 批量回执领域投影；单路卡片、后端契约、积分扣费与钱包余额刷新不变。
- 已存在的 batch billingSummaries 不受影响。
- 若真实服务端没有向 Timeline 写入对应 billingSummary，则仍需服务端结果映射修复；当前迁移源限制为只读，本任务不修改后端。

## 回滚

撤销 `BatchReceiptProjector` 对 `CallReceiptProjector` 的补齐与新增测试即可回到原投影；无需数据迁移。
