# 任务结果已读确认技术方案

## 方案

`BatchReceipt` 保留后台已有的 `executionStatus`。`VisibleTaskResultRead` 有执行字段时只接受 FINISHED；无执行字段时沿用旧终态白名单。继续要求无运行中子项、非积分拒绝、当前账号且页面可见。实时 ReceiptMessageMapper 与历史 BatchReceiptProjector 共享该模型，不改变 PENDING 的业务含义。

已读成功去重、失败可重试和生命周期恢复原本就存在，本次不将它们描述为新增修复。此前测试手造 INCOMPLETE，未覆盖后台真实的 PENDING/FINISHED 字段组合，因此不能证明此缺陷已解决。

`ConversationRoute` 将现有账号 journal 接入 Host；固定 operation=taskResultRead、result=started/succeeded/failed、failureKind 和有效 sessionId，不记录正文/号码/凭据。不再用 assert print，只有 taskResultRead 允许 32 位 hex sessionId，其余诊断保留原 UUID 规则。回调异常隔离，不能阻止 PUT 或破坏成功去重。

## 接口与兼容性

继续调用 `PUT api/assistant/task-list/items/AGENT_CONVERSATION/{sessionId}/read`，不增加字段、不修改资源 ID、签名或后端响应。新增回调为可选，既有测试和调用方保持兼容。

## 风险与回滚

诊断异常隔离已测试。回滚仅撤销本次 executionStatus 解析、已读门禁和 journal 接线及对应测试，不需要数据迁移；现有未提交的结果观察、SSE 历史等变更不属于本修复回滚范围。后台业务代码未修改；现场需安装包含本次源码的版本再验收，自动测试不代表手机已生效。
