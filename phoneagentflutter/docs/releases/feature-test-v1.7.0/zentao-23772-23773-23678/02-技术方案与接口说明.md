# 通话异常终态结果同步技术方案

## 方案

在现有会话历史/timeline 读取上增加纯 Dart 结果分类与身份去重：物理通话终态只触发结果观察，不直接推导业务成功；结果读取按 sessionId、taskId、callAttemptId 和当前 generation 校验。读取到结构化终态后先合并消息，再清除同步状态，最后触发任务列表 provider 失效。同步达到上限时退出等待并保留可恢复的未确认提示。

## 影响模块

- `ConversationOutcomeFlow`：统一结果分类、晚到读取和结果确认回调。
- `ConversationCallController`/`conversation_call_binding`：所有物理终态进入观察；结果确认和未确认分别收口。
- `ConversationController`/`conversation_providers`：结果确认后清理页面同步提示并幂等刷新任务列表。
- 结果观察纯 Dart 模型和定向测试：覆盖成功、业务失败、传输失败、重复结果和旧 generation。

## 接口与兼容性

不新增后端接口、不改变数据库或积分协议；复用现有 `ConversationHistoryRepository.restore`。新增回调均为可选或由现有 provider 注入，旧调用方保持兼容。未确认状态不伪造成功，重新进入会话仍可通过既有 restore 读取。

## 回滚

若真实回归发现问题，可关闭新增终态观察入口，恢复原有 `_sync` 的调用条件；无需数据迁移，已写入后台的事实不受影响。
