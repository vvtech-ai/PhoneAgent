## 复现步骤记录

### 线上问题复现

1. test 环境登录并记录 `sessionId`、`taskId`、`callAttemptId`。
2. 发起单路/多路外呼，在接通或结束阶段执行已授权的断网、异常挂断，或等待积分/业务失败回执。
3. 保存客户端 diagnostics，并按同一身份读取 220 日志。
4. 对照“物理终态 → SSE/transport → 结果写入 → timeline 读取 → 页面状态”。原问题的特征是后台已经出现结果提交，当前页面仍显示加载/思考中，重新进入会话后结果出现。
5. 修复后的通过条件是当前页面直接显示最终成功/失败，任务列表同步更新；无结果时显示可恢复未确认状态。

真实外呼、断网和积分消耗属于外部操作，当前只完成日志证据和本地回归，未擅自触发。

### 本地回归复现

使用 fake history/event stream 重放以下时序：首次读取没有最终回执，下一次读取返回 `CALL_OUTCOME_REPORTED` 或批量终态；随后重复同一结果并投递旧 generation 的 hangup。断言消息合并、同步提示清理、任务刷新幂等和 `unconfirmed` 超时出口。

对应入口：

- `test/features/conversation/conversation_result_observation_test.dart`
- `test/features/calls/conversation_call_flow_test.dart`
- `test/features/conversation/batch_conversation_lifecycle_test.dart`
