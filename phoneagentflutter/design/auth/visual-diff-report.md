# Auth 视觉差异与证据

2026-09-16，输入 HTML 0cd58de9、24节点 computed style、真实 Android Flutter 截图。已打开设计 login、设备 login/invitation 图逐项检查，不是只凭构建通过。

## 证据

- 原型：`.local/design-auth/previews/login.png`、`activation.png`，390×793业务裁剪。
- Android：`.local/auth-validation/login.png`、`invitation.png`，900×1600 Flutter surface、逻辑宽600dp；系统栏不在 surface 中。
- 普通入口整屏：`.local/auth-validation/default-app.png`，由 adb 截取，检查真实系统栏。
- 关键几何：Widget固定390×793测试，表单x42/w306、CTA49高/顶部约568、Logo107×98、输入56+边框2。

## 对比结果

Logo/标题/副标题/两个字段/蓝色CTA的层级、顺序、资源、圆角、浅灰背景与原型一致，未发现裁切、缺字、遮挡、错误状态栏。大屏只扩展居中留白，表单宽度上限320dp，不拉伸图片。

邀请码按 v65 增加返回登录，空邀请码CTA禁用；这是行为优先的有意差异。因多了返回控件，整组居中位置不同，不能以此判为丢失设计。

系统字体的字形和文字宽度不逐像素一致；沿用用户允许平台差异的决定。小屏/大字验证码按钮改纵向排列，为可访问性适配；基准尺寸仍横向。渐变与文本仅做视觉检查及 token 对照，未执行全图像素差分，不宣称100%像素一致。

原型上下大段留白是居中表单设计；背景填满窗口，未发现删系统底栏后固定画布造成的额外空白。截图无大面积非设计白屏/黑屏。

不适用：导航栏、列表、FAB、mask裁剪等本批不存在的组件。iOS未在本批跑页面，因此无iOS视觉通过结论。

结论：本批 Android 表单自动验收可通过，保留字体与适配差异记录，后续不以反复对比旧安卓像素作为开发主线。
