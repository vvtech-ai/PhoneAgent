# 停止任务暂态反馈统一顶部展示

## Why

停止请求同步暂未返回终态时写入通用 notice，页面将其渲染进对话时间线；终态完成没有清理该 notice。已受理后的再次停止还可能重新发出停止请求。用户要求取消、异常与中断的操作反馈使用顶部状态，真实业务正文保留。

## What Changes

- 增加会话独立 transientStatus，仅用于当前操作的顶部反馈，不进入消息账本或 timeline。
- stop binding 管理开始、受理、未决、失败、终态及失效的状态生命周期；终态投影立即清理过渡状态。
- 已受理且无部分失败的重复操作只同步，不重复 stop 请求；明确失败项仍可显式重试。
- 同账号同会话的批次停止已受理后，退出再进入仍恢复停止等待或明确失败项的重试状态；只用可信结果撤销该状态。
- 后台提交 `PENDING / EXECUTION_ERROR` 且路由仍未取得终态证明时，保留错误回执展示，但不将其当作停止已结算的凭据，不因跨页恢复重新开放停止。
- 停止请求已发出但回执未返回时退出再进入，保持原请求在途门禁；迟到回执更新重进页面，明确请求失败后才释放重试入口。
- 停止按钮禁用期间在原圆形控件内显示三个点的处理中效果，结果就绪后恢复原控件。
- 页面显示简短可操作顶部状态，保留现有恢复错误与结果整理优先级。按本次批准的体验，在原思考卡位置原位显示一张临时任务处理进度，停止后立即禁用原按钮，等待可信结果期间不因一轮同步结束重新开放。

## Impact

仅 Flutter 会话停止编排、会话状态与现有顶部展示，复用既有停止 API、批量身份和恢复端口。无数据库、服务端、SIP、权益或真实外呼变更。
