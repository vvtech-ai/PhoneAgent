## ADDED Requirements

### Requirement: 停止任务的操作反馈与连续进度

客户端 MUST 将取消、停止未决及停止失败反馈显示为当前操作的简短顶部状态；停止与整理结果期间 MUST 在原思考卡位置原位显示一张临时任务处理进度，MUST NOT 写入业务消息、持久历史、自动播报或残留在真实终态。真实失败 MUST 保持可见和可恢复，不因收起暂态丢失业务正文。

#### Scenario: 重复点击与停止未决

- **WHEN** 批量停止请求在途时重复点击，或已受理后仍无最终状态再次同步
- **THEN** 当前请求只执行一次，原圆形按钮位置和尺寸保持、立即禁用并以三点效果表示处理中；原思考卡位置连续显示任务处理进度，顶部显示处理/同步状态，无停止技术正文或重复 AI 思考占位

#### Scenario: 超过首轮同步时限

- **WHEN** 单路或多路停止已受理，但首轮有界同步结束仍未返回可信结果
- **THEN** 底部按钮仍禁用，临时进度卡保持原位置及身份；顶部允许只读同步，不重新停止，不增加无限轮询

#### Scenario: 停止受理后退出再进入

- **WHEN** 同账号同会话的批量停止回执为已受理且无失败项，页面退出后恢复时批次仍活跃、可信结果尚未返回
- **THEN** 恢复原批次的停止等待门禁与任务处理进度，底部停止按钮禁用，顶部仅只读同步，不再次发送停止请求；未停止的活跃批次仍可首次停止

#### Scenario: 停止请求在途时退出再进入

- **WHEN** 已确认的 stopBatch 请求尚未返回回执，页面退出并立即恢复同账号同会话同批次
- **THEN** 重进页面保持三点处理中与停止按钮禁用，原请求迟到成功后转为只读同步或明确失败项重试；原请求明确失败后显示可重试错误，不重复自动发出停止请求

#### Scenario: 部分失败及终态的跨页恢复

- **WHEN** 停止回执明确有失败项，或恢复账本已出现同一批次的可信终态
- **THEN** 前者保留显式重试，后者撤销停止暂态及门禁；不得用其他账号、会话或批次的回执改变当前交互

#### Scenario: 执行错误回执仍缺停止终态证明

- **WHEN** 已受理停止的同一批次提交 `PENDING / EXECUTION_ERROR` 回执，且仍有 `UNCLEAR` 路由未取得停止终态证明，随后退出并重新进入
- **THEN** 客户端显示已提交的错误回执，但保持停止门禁与待核对反馈，不重复发送停止请求；错误回执及会话 `INCOMPLETE` 本身不得清除已受理状态

#### Scenario: 从停止过渡到结果整理

- **WHEN** 已观察到通话物理结束且仍等待业务结果
- **THEN** 同一临时卡原位更新为整理结果，不先消失再追加；真实思考与正文保留，结果就绪后恢复现有输入或播报控制，评分和录音晚到不阻塞恢复

#### Scenario: 终态晚到

- **WHEN** 本次 command / batch 的可信终态到达
- **THEN** 立即撤销所属顶部过渡状态，保留结果和业务正文；迟到停止回调不能重新显示旧状态

#### Scenario: 有界观察耗尽仍无可信结果

- **WHEN** 原结果观察达到截止时间并反馈本批结果尚未确认
- **THEN** 原临时进度卡转为静态未确认说明，不持续加载或伪造终卡；停止按钮继续禁止重复操作，保留原身份、发送门禁与只读补查，卡片外不重复追加技术正文

#### Scenario: 真实停止失败

- **WHEN** 停止 API 失败或存在明确失败项
- **THEN** 顶部保留简短错误与显式重试入口，不伪造成功或自动重发；恢复成功终态后撤销错误

#### Scenario: 顶部优先级

- **WHEN** 停止暂态与真实恢复错误或结果整理阶段交错
- **THEN** 真实错误和结果阶段仍按既有合同可见，停止反馈不覆盖其他模块的 notice 或业务结果
