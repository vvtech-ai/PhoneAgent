# 职责与兼容

Flutter：原生只交付已 verified 且商品匹配的材料；token 不同的交易标记为原交易恢复，客户端不得授权当前订单。控制器在创建订单前恢复；购买期间收到旧交易交给同一账号 verifier，以服务端原单为准。新订单仅结束本地流程，保留迟到付款恢复，不宣称 Apple 交易已关闭。旧交易失败不 finish，不自动再次扣款。

Java：Apple 签名、环境、商品、账号、数量、幂等和退款合同保留。原币种与千分金额为权威；人民币字段仅为兼容投影，不参与 Apple 原币回执有效性判定。数据库/旧 API 的非空现金字段暂保留，不将其 0 展示为 Apple 实付，避免影响旧客户端及第三方支付。发票继续独立按人民币适用性判断。无原币的历史回执仍走严格旧合同，不据后台报价补造原币。

影响入口：积分/会员新购买、原单继续、启动/通知恢复。身份：账号、transactionId、appAccountToken、orderNo。无任务编排共享规则变化；相邻回归 DEVICE-01（账号/平台隔离），新增 APPLE-MONEY-01、APPLE-RECOVERY-01/02/03。

## 实现补充
新订单关闭失败或状态未定时保留其查询入口，不宣称本次没有付款；独立新订单已付则展示它自己的真实结果。UUID 按大小写无关语义比较；共享验单请求仍分别核验每个调用方的订单身份。PurchaseController 已有统一账号/订单状态编排职责，本次复用 helper 和既有 launch 扩展，不另建状态机；超过默认行数的控制器职责未扩大到数据访问或原生支付实现。
