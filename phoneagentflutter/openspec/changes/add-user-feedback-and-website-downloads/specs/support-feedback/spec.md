## ADDED Requirements

### Requirement: 用户反馈完整提交
客户端 SHALL 提供描述、图片、联系方式、可选日志和提交的单卡片表单。

#### Scenario: 内容校验与失败保留
- **WHEN** 描述为空白、超过2000码点、联系方式超过200码点或图片未处理完成
- **THEN** 禁止上传并显示可理解提示；正常请求失败保留所有输入。

#### Scenario: 图片处理
- **WHEN** 用户选择最多6张原图不超过10MiB的设备可解码图片
- **THEN** 处理为每张不超过2MiB的JPEG/PNG/WebP，其他格式转JPEG，预览等于实际提交附件；处理失败不提交原图。

#### Scenario: 日志重试及隔离
- **WHEN** 勾选日志并提交失败后重试
- **THEN** 重用原请求身份与同一日志快照；整体成功后才确认原水位，清理失败不重复提交；账号变化不发送旧草稿。

#### Scenario: 离开草稿
- **WHEN** 用户带内容离开未成功表单
- **THEN** 确认是否放弃，离页或重启不持久保存草稿。

#### Scenario: 标准离页确认与图片超选
- **WHEN** Android 或 iOS 用户离开有内容的反馈页
- **THEN** 复用 NativeBusinessDialog 标准确认外观，继续填写保留草稿、放弃返回，处理中禁止返回且不重复弹窗
- **WHEN** 本次选择超过剩余图片数量
- **THEN** 整批拒绝并提示“本次选择的图片超过可添加数量，最多还能添加 N 张。”，保留已有表单和图片

### Requirement: 双端日志设备环境
Android 和 iOS SHALL 在日志包和设备摘要中提供实际安装 App 版本/构建号、系统版本、品牌、厂商、型号及可取得的硬件机型标识；Android 另含 API level。不增加序列号或用户设备名称，App 版本按用户最新指定为 1.0.53（46）。

#### Scenario: 签名协议兼容
- **WHEN** 日志通过原生 readEnvironment 读取新增硬件字段
- **THEN** 原 readC1 返回和签名字段保持不变，不把新增日志字段送入严格 C1 公参。

#### Scenario: 相同快照上传
- **WHEN** 设备信息可取得且准备普通日志或勾选日志的反馈
- **THEN** ZIP 内 device-environment.json 和上传 deviceInfo 取自同一不可变快照；网络失败重试保持请求、日志字节及快照不变。

#### Scenario: 元数据读取失败
- **WHEN** 准备时原生读取失败
- **THEN** 保留日志并写 available=false，上传可重试读取真实信息，不修改原 ZIP；读取失败不上传假信息，账号切换不发送旧快照。
