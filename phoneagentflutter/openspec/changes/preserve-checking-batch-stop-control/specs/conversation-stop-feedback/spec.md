## ADDED Requirements

### Requirement: 断流后活跃批次保留真实停止入口

客户端 MUST 根据原批次运行事实保留底部停止入口，不因事件流失败使会话进入 ready 而退回麦克风。停止 MUST 复用既有确认、身份及防重流程，MUST NOT 只替换图标、重复拨号或自动播报临时反馈。

#### Scenario: 核对中首次停止

- **WHEN** 原批次仍有 CALLING / CONNECTED / VERIFYING 路由，断流及前后台恢复后会话为 ready，顶部与原卡片仍显示执行或核对
- **THEN** 底部显示可点击停止按钮，确认后对同 session / batch 真实调用一次 stopBatch，不重复启动 Agent 或外呼

#### Scenario: 停止在途与受理后等待

- **WHEN** 用户点击停止且请求在途，或停止已受理但可信终态未就绪
- **THEN** 原圆形按钮显示三点并禁用，重复点击无新停止、拨号或 TTS；原思考位置连续保持任务处理进度

#### Scenario: 汇总、耗尽与终态

- **WHEN** 全部逐路可信结果已齐等待汇总，或有界观察耗尽，或同批次可信终态到达
- **THEN** 前两者不重新开放首次停止入口，可信终态沿原 owner 清除停止暂态并恢复既有输入或播报控件；静态历史不新增停止能力

#### Scenario: 双端与普通语音

- **WHEN** Android / iOS 使用同一批次事件，或普通任务没有活跃批次
- **THEN** 双端使用相同 Dart 准入；普通语音输入与播报打断的既有行为保持
