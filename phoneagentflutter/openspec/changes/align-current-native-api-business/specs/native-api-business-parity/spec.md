## ADDED Requirements
### Requirement: 接口与新增业务完整对齐
客户端 MUST 对照aiassistant_app正式调用链补齐有效能力，保留已实现功能及Flutter样式/共用控件，必要新增交互参考AIAssistant1。
#### Scenario: 新增业务入口
- **WHEN** 原生正式入口存在Flutter缺失能力
- **THEN** 补齐接口、成功失败恢复及双端接线，复用Flutter组件，不复制原生视觉体系
### Requirement: 请求与结果不确定性
客户端 MUST 按类型设置超时，已受理任务不自动重放；挂断丢失响应先只读核实，停止受理后结果继续收敛。
#### Scenario: 挂断响应丢失
- **WHEN** 同一通话挂断失败但查询已进入ENDING或CANCELLING
- **THEN** 继续观察物理终态，不重复挂断，不用NOT_FOUND假报结束
### Requirement: 批量事实与结果分离
客户端 MUST 接收空文案进度并按phase解释物理状态，防旧版本/旧attempt回退，以正式回执为结果。
#### Scenario: 物理关闭但结果待整理
- **WHEN** 事件物理FAILED但phase为RESULT_PENDING
- **THEN** 显示处理中，不计为业务失败或完成
### Requirement: 异步交互与语音归属
客户端 MUST 将确认、字幕、播报及ASR回调绑定当前交互身份，零音频不报告成功，批次总结去重。
#### Scenario: 确认等待期间交互变化
- **WHEN** 新pending身份替换旧确认
- **THEN** 取消旧提交，历史仍可展示但不可执行

### Requirement: 新运行时恢复活动批次
客户端 MUST 读取会话详情可选activeBatchId与activeCommandId，恢复原批次只读进度与停止身份，不重发需求或外呼；缺字段保持兼容，已有持久终态优先。
#### Scenario: 重进仍在执行的批次
- **WHEN** 会话详情返回活动批次但原SSE已不在本进程
- **THEN** 保留输入占用并查询原批次进度，最终回执到达后恢复输入；确认停止直接针对原batch
### Requirement: 任务文件保存查看闭环
客户端 MUST 使用现有共用卡片支持已保存模板/回执查看，打开前及恢复前台只读检查文件；删除后允许显式重新下载，不自动上传或下载。
#### Scenario: 文件在系统中删除
- **WHEN** 当前owner的本地文件不存在
- **THEN** 清除已保存状态并允许重新下载，其他读取异常不冒充删除
### Requirement: 零音频与播报长按
客户端 MUST 在零音频complete后最多新建一次合成连接，并保留多句失败；播报时短按停止、300ms长按仅在无其他任务占用时启动ASR，松开/取消对应同一输入。
#### Scenario: 两次无音频
- **WHEN** 两次合成都返回零音频
- **THEN** 显示失败，不报告播放成功，不再重试
