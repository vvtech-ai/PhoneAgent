## ADDED Requirements

### Requirement: 道歉模型反馈使用单次操作身份

道歉会话 MUST 为每次成功模型切换反馈及模型选择回显保留独立交互身份。模型 ID 和重复文案 MUST NOT 代替操作身份。相同操作的重复回调 MUST NOT 新增消息，旧查询 MUST NOT 改写当前模型、反馈或 pending。

#### Scenario: 重复返回同模型

- **WHEN** 已确认道歉音色后连续切换 A→B→A→B
- **THEN** 每次成功反馈按操作追加，同模型同文案仍保留；旧消息正文、首次位置、Consent 和已选卡快照不变

#### Scenario: 重复选择同模型选项

- **WHEN** 两次从缺少音色的模型选择同一已有音色模型
- **THEN** 每次原提问、选中失活卡、用户回显和后续反馈保持独立顺序；旧卡点击不能触发新查询或请求

#### Scenario: 快速切换与重复回调

- **WHEN** 旧模型查询在新操作之后成功或失败，或当前模型变化通知重复到达
- **THEN** 只有当前代次结果可展示，重复通知不追加反馈，原 pending 不被消费或触发拨号

#### Scenario: 首次提交后重复文案的 opening 事实

- **WHEN** A→B→A→B 后首次提交，后端返回最终 B 反馈的 opening，随后重复同一事实及返回普通任务回复
- **THEN** opening 仅接管本次提交锚点下最后 B 记录，先前 B 反馈、Consent 和中间 A 均保留原位置；同事实不重复，普通任务中相同文案回复仍独立保留
