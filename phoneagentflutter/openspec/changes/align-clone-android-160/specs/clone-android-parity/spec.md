## ADDED Requirements
### Requirement: 双端克隆遵循旧 Android 1.6.0 业务流程
Flutter Android 和 iOS MUST 使用一致的指定模型入口、删除后重建、默认音色刷新与失败路由；系统权限与原生 SDK 可保留平台适配。

#### Scenario: 指定模型克隆
- **WHEN** 用户从模型音色列表点击声音克隆
- **THEN** 自动选择该模型并执行现有准入流程，不要求再次选择模型

#### Scenario: 删除后重新克隆
- **WHEN** 删除已有克隆后重新进入
- **THEN** 按最新目录和有效录音决定恢复或认证，两端同条件进入相同业务页面

#### Scenario: 未设默认返回
- **WHEN** 新候选就绪但未设置默认并返回
- **THEN** 由后台选择系统音色并核对真实目录，不使用固定供应商音色名单

#### Scenario: 生成与默认音色
- **WHEN** 本次新生成就绪并返回实际扣费及余额
- **THEN** 仅提示一次扣费；设置默认后对应模型行显示我的克隆音色

#### Scenario: 试听
- **WHEN** 用户试听克隆音色
- **THEN** 只对可恢复的下载失败重试，明确配置 iOS 播放会话，失败保留诊断而不重放生成请求

#### Scenario: iOS 采集结束后的试听交接
- **WHEN** 试听已取得媒体租约，SDK 采集 owner 已释放，应用在前台且无通话，当前会话仍为录音类别
- **THEN** 先停用该录音会话，再设置 Playback 并激活；停用失败如实记录，不继续播放或伪造释放成功

#### Scenario: 延迟重试期间开始新的采集
- **WHEN** 试听准备的有界重试执行前出现新的采集 owner 或插件已失效
- **THEN** 拒绝本次准备，不停用或重设新采集的音频会话
