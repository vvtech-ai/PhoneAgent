## ADDED Requirements

本批候选增量合同复用可空 Boolean `phoneAvailable`，经 search / showOptions / 实时 DTO / 账本投影保留；false 显示固定“暂无可拨打电话”，字段缺失保持未知，不能推断为可拨或不可拨事实。名称、地址、ID 和顺序仍来自原权威候选，不增加重复的同义提示字符串字段，不由客户端重新筛选。

### Requirement: 普通餐厅推荐只显示可拨打候选
普通附近、区域、菜系和品牌多门店推荐 MUST 消费后端已按可拨打号码筛选的候选，不在客户端另建过滤/排序规则；缺少号码且没有指定店名例外的门店 MUST NOT 作为可拨打推荐展示。空结果、定位缺失和搜索服务异常 MUST 区分。

#### Scenario: 混合候选与全无号
- **WHEN** 普通搜索包含有号/无号门店，或没有任何符合条件的有号门店
- **THEN** 仅显示后端有号推荐；全无号时明确未找到符合条件且有可拨打电话的餐厅，不让用户先选无号门店再被要求换店

#### Scenario: 品牌多家门店不能走无号例外
- **WHEN** 用户按品牌搜索得到多家相关门店，或上限为一但原始相关候选不止一家
- **THEN** 服务端在数量上限前过滤全部无号候选，选项只展示有号门店并按实际身份编号；不会展示无号项供选择后再要求换店

### Requirement: 指定门店无号时同步告知
明确指定餐厅且在候选上限前只有一个真实相关门店命中时，客户端 MUST 保留后端提供的该无号门店并在候选显示时同时标识“暂无可拨打电话”，结合对话说明已找到但没有可拨打电话；不得等用户选中后才告知，也不得将其显示成未找到餐厅或直接拨打。

#### Scenario: 明确店名但无电话
- **WHEN** 用户指定的门店真实命中而后端标记无可拨打号码
- **THEN** 展示真实门店名称/地址及无号说明，不自动换店、不生成无号码拨打确认、不编造号码；用户主动补充号码仍走现有校验和确认

### Requirement: 实时与恢复候选一致
号码可用性、无号说明和选项身份 MUST 经原候选投影与账本恢复一致展示；位置授权、记忆采用/保存和拨打确认继续沿原任务合同。前端不得用重搜或当前结果重排已提交历史候选。

#### Scenario: 定位授权后重复搜索和恢复
- **WHEN** 用户授权定位后查询、重复查询，再从任务列表恢复同一任务
- **THEN** 有效新搜索使用原定位合同，已提交候选的身份/顺序/无号说明保持，旧卡不复活且不自动拨号或重新询问已处理的保存确认
