## ADDED Requirements

### Requirement: 会议确认实时同步与脱敏补问去重
收到当前会话的批量确认补问事件时，客户端 MUST 在允许用户确认前通过现有 timeline 同步结构化确认卡，复用原 pendingToolCallId；历史读取 MUST NOT 重放工具、外呼或权限。同步失败 MUST 显示可重试状态，SSE 结束 MUST NOT 覆盖失败状态。补问历史只保留 prompt、缺少内部 id 时，客户端 MUST 按同轮 commandId、toolCallId 与相同文案替换实时补问，MUST NOT 误删其他轮次提问。

#### Scenario: 确认事件仅含文案
- **WHEN** ASK_USER 只携带当前批量确认提示，timeline 已保存 confirmBatchTask 快照
- **THEN** 当前对话在外呼执行前显示完整确认卡及原确认文案，不自动确认或拨号

#### Scenario: 脱敏历史到达
- **WHEN** 同一补问的实时对象含 id，历史工具参数只含 prompt
- **THEN** 文案只显示一次，后续轮次不同工具的提问仍正常显示

#### Scenario: 同步失败或账号切换
- **WHEN** 确认历史同步失败，或读取期间账号已切换
- **THEN** 失败可恢复且流结束后仍保留，旧账号迟到快照不覆盖当前会话

### Requirement: 当前通话收尾显示临时思考反馈
系统 MUST 复用既有通话awaitingOutcome事实显示原思考卡，物理挂断不等同最终任务完成。成功主动停止 MUST 保持静默；实际失败、部分挂断失败和收尾未确认仍保留重试反馈。

#### Scenario: 当前电话结束等待最终结果
- **WHEN** 本页明确确认的电话已结束，但Agent最终结果尚未返回
- **THEN** 关闭通话展示并恢复输入，在原对话尾部显示“正在整理通话结果”的思考卡，结果到达后移除，不持久化卡片

#### Scenario: 任务列表历史入口
- **WHEN** 用户从任务列表打开历史会话，没有本次启动的通话观察状态
- **THEN** 展示已有历史，不生成通话收尾思考卡或重放外呼

#### Scenario: 多路全部结束等待汇总
- **WHEN** 当前发送轮次的临时批量进度已覆盖全部结束项目，但最终汇总尚未返回
- **THEN** 复用原思考卡反馈收尾，最终回执或停止后移除，历史恢复不生成该反馈

#### Scenario: 手动停止成功
- **WHEN** 普通或批量停止请求被服务端受理且同步完成
- **THEN** 保留原停止和同步动作，不增加成功提示；部分失败仍允许重试

### Requirement: 评分资格请求使用实际客户端版本
客户端 MUST 对单路callId和批量batchId通过当前SDK任务评分端点查询资格，并发送Android/iOS实际安装版本；不得发送写死1.0.0、伪造v66版本或因100%抽样强制生成评分卡。版本读取等待/失败不得发出旧版请求，页面/账号退出后的迟到读取不得查询旧任务。

#### Scenario: 100%策略且当前客户端版本达标
- **WHEN** 有效终态回执查询资格，服务器返回eligible且anchor与目标一致
- **THEN** 挂载原任务评分入口，读写、奖励和重复操作沿用既有规则；服务器未返回有效资格时不制造卡片或积分

### Requirement: 任务录音和外呼UI保留v66有效交互
普通任务录音保存结果 MUST 使用一次性短暂通知，不增加卡片下方常驻保存文字；顶部关闭 MUST 不展示长按tooltip且保留无障碍说明。外呼页 MUST 不显示额外监听状态提示，发声源面板 MUST 使用深色背景、26圆角、独立选项radio和取消，选择仍只调用既有音源端口。

#### Scenario: 保存或长按关闭
- **WHEN** 录音保存完成/失败或用户长按右上角关闭
- **THEN** 保存结果短暂通知且不重复弹出，取消不通知成功；长按不出现tooltip，关闭仍沿用原点击行为

#### Scenario: 切换和取消音源
- **WHEN** 外呼时打开音源弹窗或取消
- **THEN** 显示“发声源”“选择监听声音的播放设备”及听筒/扬声器/可用蓝牙，取消保持原音源，不自动启用监听

### Requirement: 普通任务声纹跟随实际播放实例
普通任务录音 MUST 使用实际播放器的音频采样投影24柱平滑声纹；不得仅按播放状态无限模拟。暂停/完成/退出/替换 MUST 停止采样并安全释放，失败采样不得影响播放。有效采样优先，静音为最低静态柱，Android Visualizer极值/冻结有声帧按v66限幅模拟，采样不可用保持静态；旧播放实例事件不得更新当前录音。

#### Scenario: 录音首次播放和重进
- **WHEN** 播放有效录音，滚动重组后再次显示，或退出重进重新播放
- **THEN** 声纹仍由执行播放的同一实例驱动；保存或采样异常不得重置播放，不创建竞争播放器

#### Scenario: 首次引导未完成
- **WHEN** 设备未完成有效语音输入，环境检测/播报结束后任务恢复可输入
- **THEN** 显示“按住说话”及向下尖角，未按住录音的短暂状态切换不得取消这次提示；已完成设备仍保持原完成规则

### Requirement: 外呼头部采用物理接通的两阶段计时
Flutter MUST 在确认外呼后的观察页显示接通中MM:SS，首次收到物理CONNECTED时从00:00重新计时，重复CONNECTED不重置。Agent进度或转写不能替代物理接通状态；该时钟只控制展示，不参与计费。

#### Scenario: 接通前后分别累计
- **WHEN** 外呼等待后首次收到CONNECTED
- **THEN** 接通中等待时长不计入已接通时长；重复状态同步继续累计
- **AND** 物理结束、离页或账号切换停止并释放展示时钟，不自动挂断电话

### Requirement: 当前模型目录采用模型身份与发布文案
任务直接使用的模型目录 MUST 使用有效modelId与activeModelId作为选择身份，兼容仅有provider的旧目录；相同provider不同modelId不得被合并或误判重复。MUST 使用服务端displayName与appSubtitle，旧description仅作兼容，不添加来源没有的推荐标签，不改变运行时模型、倍率或声音配置。

#### Scenario: 同供应商多模型
- **WHEN** SDK目录返回同一provider的多个有效modelId，指定activeModelId且仅提供appSubtitle
- **THEN** 任务弹窗显示完整目录与发布名称/副标题/倍率，准确选中并提交modelId，后续延迟按相同modelId关联

### Requirement: 终态恢复保留同次通话有效展示锚点
ledger终态与暂态终态同属当前账号/session且同callAttemptId或可信callId时，展示 MUST 以ledger状态与正文为准，仅以同次暂态回执补缺媒体身份、metadata、结构字段和账单，MUST NOT 修改持久源事件或借用其他通话。timeline的500至599响应 MUST 保留真实失败和重试，不降级为空历史。

#### Scenario: 不完整终态覆盖完整实时结果
- **WHEN** 同次ledger终态缺少callId/账单，而实时结果已有有效callId、字段和零扣费账单
- **THEN** 显示一组回执，保留ledger状态/正文/顺序及原对象，录音/评分仍可使用有效callId查询，零扣费不丢失

### Requirement: 最新监听仅在真实音频到达后显示播放
客户端 MUST 按最新App SDK票据端点api/agent-calls/monitor/token及Runtime签名WSS连接监听；票据请求等待物理CONNECTED，保留8秒请求/10秒首PCM超时与最多三次800ms重试。MUST 仅收到有效PCM且播放适配器接受后显示正在监听，握手成功不得假报播放。音源可在有效AI通话中预选或静音时切换，不隐式开启监听、采集或外呼。

#### Scenario: 接通前开启监听并选择外放
- **WHEN** 正在接通用户打开监听并选择扬声器
- **THEN** 只保留等待和音源偏好；接通后才请求SDK票据，Runtime首PCM到达后用选中音源播放
- **AND** 结束/离页/账号变化取消等待、重试和媒体，迟到票据/PCM不得激活旧通话

### Requirement: 任务语义结果回执必须保留媒体与评价锚点
客户端 MUST 与最新独立App一致读取CALL_OUTCOME_REPORTED.callReceipt，保留同session和callAttempt的服务端callId、电话、dialogueDetail及billingSummary。恢复结果 MUST 将有效callId提供给已有录音、模型评价和任务评分路由。录音 MUST NOT 因转写暂未返回而隐藏；明确未接通的现有显示规则继续保留。

#### Scenario: 仅语义结果事件携带完整回执
- **WHEN** timeline只有CALL_OUTCOME_REPORTED携带有效callReceipt，而没有物理终态事件
- **THEN** 对话和直接任务详情显示该回执的转写与积分
- **AND** 录音、模型评价和任务评分使用该回执callId查询已有SDK接口
- **AND** 不借用其他session或callAttempt的数据、不重放外呼

#### Scenario: 转写尚未返回但存在有效录音锚点
- **WHEN** 回执有有效callId且没有明确未接通事实，dialogueDetail为空
- **THEN** 继续查询录音元数据并保留原加载或可用状态
- **AND** 不制造转写、录音文件或评价数值

### Requirement: 外呼控制遵循当前服务归属与账号契约
Flutter MUST 将单路通话状态和挂断请求路由到Agent服务，按最新App v71将监听票据请求路由到SDK服务，并为这些请求以及SDK录音和模型评价带当前账号凭据。后端尚未提供最新契约时记录待确认，不修改后端或回退到匿名请求。

#### Scenario: 不同服务前缀的开发环境
- **WHEN** Agent与SDK配置为不同前缀
- **THEN** 单路状态、挂断访问Agent；监听票据访问SDK的api/agent-calls/monitor/token，均携带Bearer
- **AND** 录音和模型评价访问SDK且携带Bearer，录音内容URL和保存作用域使用SDK基地址，账号切换拒绝旧响应

#### Scenario: 原生监听握手
- **WHEN** 当前账号开启外呼监听
- **THEN** Runtime监听WSS握手复用现有C1签名和Bearer传输，不能仅凭ticket使用匿名socket；账号切换关闭旧握手，不重放已接受的音频会话
- **AND** 握手成功后原监听音源支持听筒/外放切换，停止或离页释放平台播放，未授权不创建外呼

### Requirement: 结构化任务结果采用原版任务回执
Flutter MUST 按v66结构化任务字段及业务结果展示任务完成、任务失败或结果确认中，复用现有转写、录音、积分、模型评价与任务评分组件，不能把电话物理结束当作任务成功。

#### Scenario: 完成失败及异常的结果卡UI
- **WHEN** 当前任务或恢复任务展示完成、业务失败、技术异常或尚未确认的结果
- **THEN** 使用v66正式PureVoice结果卡的280宽上限、16圆角、16/14内边距、绿色/红色/黄色渐变；标题14/18加粗，字段为12/16左右两列，失败/异常保留真实原因
- **AND** 服务端有效账单在相同结果卡内按原分隔线和计费时长、模型费率、扣除积分、剩余积分双列显示；单路不新增“积分结算”标题，零扣费仍显示，业务失败或异常不隐藏账单
- **AND** 同一账号/session/attempt内的工具结果或通话事实返回账单时，实时及ledger恢复投影保留最新有效账单；无账单不合成扣费或余额，不从其他attempt借用积分

#### Scenario: 服务端返回结构化终态与附件
- **WHEN** 当前或恢复任务返回业务结果、结构化字段、转写、账单及有效callId
- **THEN** 展示对应任务结果与返回内容，并按原版服务端显隐规则展示录音、模型评价和任务评分
- **AND** 不合成缺失转写、录音、账单或评分

#### Scenario: 普通任务回执
- **WHEN** 服务端返回无结构化字段的任务结果标题和正文
- **THEN** 使用返回的headline作为标题，保留有效正文；只有已展示为转写的相同内容才避免重复正文，不额外替换为“通话结果”

### Requirement: 播报期间保持原语音停止控件
系统 MUST 在TTS播报期间隐藏麦克风和录音引导，保留原输入行停止控件；点击 MUST 通过既有播报中断端口停止TTS，不因此启动录音。结束后 MUST 恢复按住说话，首次符合原VoiceGuidePolicy的待命显示“按住说话”和向下箭头；按住、取消、短按仍使用v66文案与完成规则，不重置设备引导偏好。

#### Scenario: 开场播报后第一次录音
- **WHEN** 用户进入任务正在开场播报，然后播报完成或手动停止
- **THEN** 播报时没有录音按钮，停止不调用ASR或提交；结束恢复麦克风，未完成引导的设备首次显示“按住说话”和向下箭头

### Requirement: v66任务模型弹窗与选中倍率
Android/iOS任务模型选择弹窗 MUST 按v66内容撑高、最大宽度420及安全区布局，小屏大字可滚动。入场及原刷新操作 MUST 通过当前Agent端点和Bearer/C1获取真实模型延迟，成功显示毫秒数字及原颜色，失败显示原不可用，不使用合成延迟。任务输入行选中标签 MUST 显示后端有效倍率；缺失倍率不编造默认值。

#### Scenario: 入场刷新与关闭
- **WHEN** 用户打开模型弹窗、刷新或关闭后重进
- **THEN** 展示内容高度及当前模型真实延迟，重复刷新防重，旧弹窗或旧账号响应不更新新页面，不因此切换模型或发起电话

#### Scenario: 模型目录恢复与任务标签
- **WHEN** 目录加载失败后用户重试成功，或用户成功选择模型
- **THEN** 弹窗为有效目录刷新延迟，任务标签同步模型名及倍率；网络失败仍保留原重试入口

### Requirement: v66状态行与多行草稿
对话 MUST 在同一44dp行渲染七段声纹、状态及无底色播报按钮；透明关闭按钮 MUST 与喇叭水平中心对齐，不保留独立声纹占位。文字输入 MUST 支持1–5行、回车换行、内部滚动及键盘和安全区后85%可用高度展开编辑；收回隐藏键盘并保留文字/光标，以单行摘要恢复编辑。AI输出期间 MUST 可编辑，发送沿用原提交门禁和接受后清理草稿。

正常状态文字 MUST 使用v66有效源码的「语音待命中...」「正在聆听...」「AI 思考中...」「AI 回复中...」，优先级为实际错误、原版环境检测、AI回复、聆听、思考、待命，不新增连接/识别阶段提示或暂停文案。喇叭下面 MUST NOT 另设语音提示行；原版按住/短按引导仅复用麦克风旁已有的浮动提示，不挤占对话布局。极小键盘视口允许同一状态行进入对话滚动区，关闭按钮仍固定。

#### Scenario: 原版提示位置与内容
- **WHEN** 正常待机、连接语音、识别、思考或播报，以及首次/短按使用麦克风
- **THEN** 头部仅显示一行原版声纹状态，连接过程不新增提示；原版「按住说话」「请按住说话，说完松开」只显示在麦克风旁，实际失败复用原状态行并保留重试
- **AND** 发声按钮只保留原版无障碍描述，不显示新增长按提示气泡

#### Scenario: 忙碌编辑与收回
- **WHEN** 用户在AI输出期间编辑多行草稿、展开后收回再恢复
- **THEN** 保留当前任务草稿和光标，不自动发送，回车不触发提交

### Requirement: v66环境检测与临时录音文字
系统 MUST 在任务头部原状态行按v66顺序展示「正在检查网络连接」「正在连接大模型服务」「正在检查外呼通道」「任务执行环境检测通过」，最短展示时长分别为300、350、350、500毫秒。检测复用当前网络适配和模型查询，失败不得展示通过；外呼阶段为原版执行前检查展示，不代表真实电话或SIP验证。MUST NOT 恢复登录初始化阻断页或建立第二套任务状态机。

系统 MUST 同时保留v66正式PureVoiceStage链路中的检测提示框，标题为「正在初始化任务执行环境」，三行仅为「网络连接」「大模型服务」「外呼通道」，逐步显示原版等待、检测、就绪或不可用详情及圆点颜色。新入口使用92%宽度卡片；已有对话内容时放在时间线尾部，通话展示时隐藏。全部通过短暂展示后消失，失败或等待实际模型响应时保留；该任务检测框与登录初始化设置页分别处理。

#### Scenario: 入场三步检测与历史内容
- **WHEN** 新任务入场、恢复已有对话或检测失败后恢复
- **THEN** 检测框按原顺序展示，历史消息仍保留；失败不假报通过，不新增检查项、按钮或页脚

### Requirement: 正式添加内容仅保留原版入口
Android/iOS正式对话的添加内容菜单 MUST 仅提供v66相册、文档及原副标题。MUST NOT 受调试构建或迁移演练开关影响，展示MOCK场景、合成资料或演练入口；测试工作台仍与正式菜单隔离。

#### Scenario: 调试或正式构建打开添加内容
- **WHEN** 用户从任务输入行打开添加内容
- **THEN** 只显示相册和文档，走现有真实图片/文档端口，不附加演练场景

### Requirement: 换行保持编辑控件稳定
输入框 MUST 在一行、多行和文字自动折行之间复用同一编辑控件，保留焦点、光标、输入法组合文本与键盘连接。仅按原版调整高度和工具位置，不因换行卸载或重新创建输入连接。

#### Scenario: 连续换行与删除恢复一行
