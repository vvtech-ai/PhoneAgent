## ADDED Requirements

### Requirement: 已显示确认提示应保留在所属时间线

客户端 SHALL 将实时确认请求的既有提示按 command/tool 身份保存在卡片后；确认、执行与普通工具清理不得删除该正文。保存正文不得额外调用 TTS 或放宽确认资格。

#### Scenario: 用户确认后卡失活

- **WHEN** 当前确认卡和提示已显示，用户明确确认并执行通话
- **THEN** 原提示仍在确认卡后、用户确认前，且仅执行一次确认命令

#### Scenario: 连续两通电话与重复事实

- **WHEN** 同 session 第一通结束后明确确认第二通，旧结果通过补查再次到达
- **THEN** 第二通观察身份保持不变，两通确认/提示/结果保留各自位置；重复补查不增加正文或语音

### Requirement: 确认及结果语音应按当前身份独立驱动

客户端 SHALL 使用现有语音控制器播报确认和结果，重复回调一次有效播报；打断不删文字，旧轮迟到事件不播，后续有效结果仍能播报。

#### Scenario: 确认提示打断后继续

- **WHEN** 当前确认提示已排队，用户打断并随后明确确认
- **THEN** 当前提示文本保留，旧播放取消，匹配结果的新播放正常产生一次

#### Scenario: 历史恢复

- **WHEN** 已完成任务重新恢复，或无提示正文的纯工具历史被读取
- **THEN** 不提交确认命令，不新增 TTS；仅展示真实已有事实，不从旧卡补造提示正文


### Requirement: 独立正文与结构卡轨迹按事实身份协调
同 command / tool 的不同 plain 正文 MUST 保留各自消息身份，只有正文一致的临时副本才可由对应 durable 副本协调；结构卡 MUST 仅隐藏所属 command / tool 的重复轨迹，不隐藏其他工具或 Agent 正文。

#### Scenario: 同工具存在独立提示和确认正文
- **WHEN** 同工具有不同已提交正文及已显示确认提示，随后真正的提示副本到达
- **THEN** 不同正文均保留，真正副本只显示一次；确认卡与旧正文不因去重而消失

#### Scenario: 联系人 continuation 返回结构卡
- **WHEN** showOptions 或 askUser 的同身份工具轨迹与结构卡同时存在
- **THEN** 仅显示对应结构卡，保留其内容 / pending / 选择行为与其他工具轨迹，不重复显示同一提示
