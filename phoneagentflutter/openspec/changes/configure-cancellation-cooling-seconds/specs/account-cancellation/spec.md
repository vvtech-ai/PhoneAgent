## ADDED Requirements

### Requirement: 秒配置与确认快照
SDK MUST 从服务配置app.account-cancellation.cooling-period-seconds读取正整数期限，默认1296000秒；范围1..1296000秒以兼容固定恢复窗口。已有申请MUST使用原effectiveAt，配置不得重算。

#### Scenario: 新确认使用刷新配置
- **WHEN** 配置从1296000刷新为300
- **THEN** 后续确认及新流程使用300秒，现有确认流程继续使用自己的持久快照

#### Scenario: 旧挑战或不合法配置
- **WHEN** 新确认配置非法，或未受理的旧挑战没有期限快照
- **THEN** 不使用猜测期限受理；旧挑战要求重新确认，已受理重放仍返回原截止

### Requirement: 客户端按单位展示
Flutter MUST 保留服务器期限快照的读取、校验和单位格式化能力，不计算或授权真实注销。2026-10-28用户进一步确认最终注销弹窗正文逐字采用需求原文，该弹窗只动态替换服务端绝对完成时间，不追加期限单位或“冷静期内”说明。单位格式化仍采用严格大于阈值和向下取整，不改现有控件及确认流程。

#### Scenario: 单位边界
- **WHEN** 秒数为86400、3600、60、30、90000
- **THEN** 时长格式化能力分别返回24小时、60分钟、60秒、30秒、1天；最终确认正文仍仅动态展示服务端完成时间

#### Scenario: 老响应与畸形数据
- **WHEN** 响应没有时长字段或字段不是有效正整数
- **THEN** 缺字段时最终确认仍按需求原文显示服务端完成时间；畸形字段拒绝，不猜测15天
