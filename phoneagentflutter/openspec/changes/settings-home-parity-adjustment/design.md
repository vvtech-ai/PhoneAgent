## Context

用户批准计划且明确退出风格仅限定入口。参考固定Android 0f8879e4的FinalSettingsHomePage/FinalSettingsPageV3和iOS bb9ff349的AISettingsViewController。当前Flutter首页日志与关于页日志共用LogEntryController；首页退出仍是左对齐普通卡片。

## Goals / Non-Goals

目标：有效首页统一布局和反馈；首页不再读取日志状态；iOS页尾退出入口双端一致；完整子页进入返回及状态刷新可验证。

范围：我的身份、语音大模型、实时翻译原音、关于PhoneAgent、解锁后开发者、Android版本更新及退出。关于页日志保留；不修改退出确认样式，不新增可信来电，不实施真实上传、认证、外呼或收费。

## Decisions

1. 新增独立SettingsLogoutButton，仅承担展示和按压生命周期。参考iOS footer：顶距16、正常按钮64高、底距16、居中EF4444/16semibold、24圆角、80%白底、78%白边框、8%阴影。按压6%红底/0.99缩放，释放或取消复原；减少动画时不缩放。大字体允许自然增高，不压缩文字。
2. SettingsPage保留10横向边距、现有半透明24圆角卡片和有效原生摘要。页尾按钮继承页面宽度；主Shell已有动态底部导航避让，不重复叠加原生128点留白。列表底部保留可滚动余量。
3. SettingsRoute完全移除日志Provider与动作依赖，AboutRoute继续在进入后自行装配。首页仅显示已批准入口；Android更新继续实读版本并显式检查，iOS隐藏OTA。
4. 不修改已有子页的已验证行为；逐项检查实际入口/返回/摘要/失败状态，发现具体差异后按不超过3个源码文件微批修正。不凭历史文档重复实现已有能力。
5. 本次在当前共享分支codex/dev_zys按文件提交，不切换或清理其他任务工作树。根tasks和问题日志仅追加本次进度，不覆盖并行任务。

## Validation

OpenSpec validate --all；Flutter3.32.0 analyze --no-pub及设置/关于/日志/模型/原音/导航直接调用方定向测试。新增双平台普通/两倍字体的入口顺序、居中按压、取消手势、减少动画、短屏可达及不装配日志Provider测试；保留退出确认取消/系统返回/失败重试。

复用隔离UI参考，合成端口运行Android/iOS正常/大字、子页返回及退出入口。源参数、测试、实际截图分别记录；原生保留日志/可信卡的已批准差异明确说明，不删改原生参考。无需每批双端正式构建；若平台工具失败，核对当前状态后有限重试并继续其他验证，不卸载或清数据。
