## Context

测试运行环境只读核验确认：指定记忆会话可用范围数量为二，而 TOOL_REQUESTED 的使用绑定候选数量为一。当前配置文件不等于实际运行数据源，现场核验以服务 Profile 与实际配置导入链为准。脱敏证据单独记录，不提交账号、候选原文或配置值。

## Decisions

1. 记忆检索返回当前 Skill 中与 query / purpose 相关的完整备选集合；用户未指定某人时不得自动挑一个替代澄清。相关性筛选与采用授权分开，选择姓氏、序号或尾号仅授权所指版本；不为补齐数量纳入无关用途或其他 Skill。
2. 记忆管理查询的安全状态与写入成功 / 业务拒绝必须保留给当前操作后续推理。未采用管理候选正文继续隔离；内部隔离说明不能成为用户回复。保存确认上下文包含真实工具回答，管理授权不等于任务采用。
3. 道歉有效模型优先当前任务选择与恢复的任务配置，再沿用普通任务全局来源；准入与确认报价共用解析。旧确认快照保持不可变，不更改全局模型或绕过钱包刷新。
4. 日志上传按实际安装版本源异步组装设备信息；失败不伪造 1.0.0（1）。版本展示、更新与日志复用同一平台事实，不添加构建常量副本。

评分经用户复核为既有逻辑，本轮不改源码、规则或测试，不增加引用或迁移锚点。

## Implementation boundaries

记忆候选分类及管理历史投影独立负责；有效任务模型新增小型 resolver 并接入两个 provider；日志版本通过既有 installed-app source 适配。大文件只改既有扩展接线，不重构通话、SIP、TTS、拨打确认或权限核心。

## Validation

先观察失败，再最小修复。覆盖两人备选→自然选一→继续→恢复→新任务、无关用途/其他 Skill；保存确认→写结果→下一模型轮和不可用查询；全局110/任务100/余额105的真实 provider 接线及反向情况；不同安装版本日志上传。执行受影响 Java 模块与 Flutter 完整回归，既有失败按名称记录。自动回归不替代部署后现场设备验收。

## Repository scope

本仓只实现任务有效模型与诊断版本接线，记忆后端合同由服务端实现；评分保持既有逻辑。

## 首轮补充证据与有界补核

新提供的首次会话实际绑定餐厅预订；四次主模型请求均已有 AVAILABLE / count=1，但搜索选店后直接补问联系人，没有调用记忆检索。未发现 Flutter 首次命令丢失 Skill 或携带记忆正文缓存；道歉本地音色 ready 提示与首个 Agent 业务回复分开验证。

在现有公共 askUser 规范化扩展点加入独立策略，只对模型准备补问的缺失资料、当前有适用记忆且未停止主动询问的情况，每命令最多补核一次相关性。使用既有完整候选分析与确认协议，补核绝不直接采用。无关 / 不可用 / 管理 / 保存确认 / 当前资料完整 / 已采纳仍沿原流程；普通正文不新增分类调用。新增餐厅与道歉首业务轮次的连续回归。主动改变决定与管理补问后重新查询分别覆盖，保持明确采用与命令授权边界。
