## Why

连续现场显示：两位相关记忆在服务端确认工具落账前被缩成一位；记忆管理结果被内部隔离标记替代；日志版本取构建常量默认值；道歉任务的准入与报价误读全局模型。

## What Changes

- 补齐记忆相关候选完整性与自然选择，保留当前绑定 Skill、账号、用途、版本及使用确认；区分可公开操作结果和未采用正文，阻止内部隔离标记进入用户说明。
- 客户端日志读取实际安装包版本；道歉准入、报价读取当前任务有效模型。
- 同步三仓规则及连续回归，沿用 1.0.52（45）测试环境 Release 签名构建。

## Capabilities

### New Capabilities
- `task-context-recurrence-guards`: 记忆候选与管理结果、有效模型和安装版本的连续合同。

## Impact

Java Agent 记忆候选与管理历史，Flutter 准入报价与日志适配。用户复核评分属于既有预期，评分源码、资格锚点、规则与已有测试全部保持。Web 仅同步共同规则。无数据库迁移、部署、真实外呼或媒体链路调整。

## Repository scope

本仓只实现任务有效模型与诊断版本接线，记忆后端合同由服务端实现；评分保持既有逻辑。
