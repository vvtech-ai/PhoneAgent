## ADDED Requirements

### Requirement: 草稿归属当前账号和任务
系统 MUST 按环境、账号和当前任务session隔离保存未发送草稿，不能串任务；发送入口接受后清除已发送持久化内容，真正未受理失败可恢复，保护后续新输入。

#### Scenario: 切换与重新进入任务
- **WHEN** A任务有未发送内容，用户退出后进入B再返回A
- **THEN** B不显示A草稿，A恢复自己的草稿；账号不同互不读取

#### Scenario: 已发送内容不能回填
- **WHEN** 用户发送后退出并重新进入同一任务
- **THEN** 已发送内容不作为草稿恢复，较晚的新输入仍保留

#### Scenario: 旧回执与发送失败
- **WHEN** 发送旧内容后用户输入新内容，然后旧请求受理或失败
- **THEN** 不删除或覆盖新输入；仅无新编辑且真正未受理失败时恢复旧输入

#### Scenario: 清理边界
- **WHEN** 用户删除某任务或退出当前账号
- **THEN** 分别清理目标任务或当前账号草稿，不影响其它账号；正常完成任务不清未发送内容

### Requirement: 拨前交互对齐旧版
系统 MUST 将积分说明放在底部按钮下方，正文灰色、星标金色#FFC400；保留有效同语种选择，拨号时明确提示，语言校验先于号码格式提醒；目录后台刷新保留列表，不可用模型明确说明且不显示推荐。

#### Scenario: 同语种和小屏积分说明
- **WHEN** 用户两侧选择同一支持语言并点击拨号
- **THEN** 选择保持，短提示要求不同语种且不拨出；积分在按钮下方、星标金色，小屏大字体不溢出

#### Scenario: 后台配置刷新和不可用模型
- **WHEN** 打开国家列表且目录后台刷新，某推荐模型当前不可用
- **THEN** 旧列表保持到新目录返回，不可用模型显示原因、不显示推荐且不能选择

### Requirement: 正常暂停与故障区分
系统 MUST 在OCR或正常中断时显示“播报已暂停，可继续交流”，真实TTS故障仍显示失败；Android/iOS共享该规则，不自动重播或改变任务执行状态。

#### Scenario: 相册打断
- **WHEN** 播报中打开OCR相册并发生系统生命周期变化
- **THEN** 停止当前播报并提示暂停，后续语音或文字仍可交互，不计为播报故障

#### Scenario: 真实故障不能伪装暂停
- **WHEN** 供应商、传输或音频输出真正失败
- **THEN** 保留失败状态，随后正常停止也不能覆盖该故障
