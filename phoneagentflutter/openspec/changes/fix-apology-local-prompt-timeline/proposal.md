## Why

道歉交互与真实任务需要不同身份和稳定插入位置。原提案采用提交时清空全部本地提示的做法，已被用户批准的 `task-orchestration-v1` 替代；不能将保留可回看的交互本身当成错误。

## What Changes

- 保持本地提示 ID 仅用于道歉确认生命周期。
- 旧卡失活且保留快照，查询只更新状态，就绪反馈按当前操作追加；不在任务提交时批量删除本地道歉历史。
- 本地记录与同身份 initial-opening / 任务账本事实原位协调，恢复不重播或伪造本地点击事实。
- 联系人回传产生新 continuation command 时，将当前 thinking 段重新绑定到该 command，并补齐回传缺失的 `showOptions` 工具卡。

## Impact

原变更涉及 Flutter 道歉绑定、联系人续接与展示。本次仅纠正规范，当前实现差距由独立 change 承接；不修改后台协议或账本事实，历史验证不能证明新合同已通过。
