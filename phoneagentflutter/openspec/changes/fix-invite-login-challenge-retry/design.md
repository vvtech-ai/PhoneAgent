# 设计

SDK 继续原子取走 challenge 保证同一时刻一个执行者；仅只读分类和旧码 verify/结果校验失败时恢复原未到期记录。redeem 必须在恢复捕获范围之外，核销异常或核销后账号初始化异常均不恢复。保留已注销邀请人专用恢复规则，不泛化推荐注册异常。

App 在现有 gateway 中识别“登录验证已过期”；仅邀请码阶段收到明确失效错误时清除 challenge/短信码并回到原登录表单，保留手机号、邀请码草稿和发送冷却，不自动发短信。其他失败继续原规则。

SmsLoginService 超过300行，仍是单一登录用例；本次仅扩展私有校验/恢复函数和已有调用，不搬动账号、积分、核销职责。两端 HTTP 字段和错误码合同不变。

实施中用户补充要求：第三方返回也进入日志。SDK 通过独立 InviteHttpExchangeLog 记录 legacy/referral 两客户端每次 HTTP 交互，包含 reqid/traceId、POST URL、参数、HTTP 状态、返回正文、耗时、异常类别；核销业务 trace 与操作身份保留在参数中。签名头不记录，密钥/token/challenge/验证码、手机号和邮箱脱敏；单字段超过16384字符标记截断并保留响应原始长度。坏JSON/非JSON返回也提供脱敏诊断，日志异常不能影响核销及错误映射。此补充不改变App接口或增加自动请求。
