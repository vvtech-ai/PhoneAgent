# 批量外呼待裁决状态展示修复

## Why

后台在批量外呼的物理线路结束后、最终业务裁决回执到达前，会发送 `UNCLEAR` 或 `PENDING` 的临时路由状态。客户端当前把这些状态落到默认“任务完成”，导致并发排队或待裁决的路被误显示为已完成。

## What Changes

- 将批量进度中的 `UNCLEAR`、`PENDING`、`ABNORMAL`、空值和未知状态统一显示为待确认，不再显示“任务完成”。
- 保留最终 `BATCH_CALL_RESULT` 的成功、失败、取消和待确认四态裁决，不改变后台事件契约或拨号调度。
- 增加批量进度状态映射回归测试。
- 续批统一线路繁忙排队文案：`LINE_BUSY_WAITING`、`WAITING_FOR_LINE`、`WAITING_CALL` 在进度卡和逐路回执均显示“等待呼叫中”，保持运行中状态与原始明细。

## Impact

仅影响 Flutter 批量外呼临时进度卡片的文案；不改变后台并发、SSE 事件接收、最终结果或通话控制。
