## Context

现有 NativeCrashImporter 已提供账号隔离、持久化后 ack、失败重试和 ZIP 归档。iOS 跟读故障缺少原生栈；认证由固定供应商 SDK 管理。

## Goals / Non-Goals

目标：可捕获崩溃在下次启动自动进入原有上传；日志能用匹配 dSYM 还原原生位置。不保证诊断就是根因结论。不升级认证 SDK，不改变认证、录音、媒体租约、计费或 UI。

## Decisions

- 独立 CrashDiagnostics 本地 Pod，PLCrashReporter 固定 1.12.0。采集由成熟库完成，不自行编写信号处理器，不在崩溃线程运行 Flutter/网络/JSON。
- 采用 Mach 异常模式、关闭符号遍历；库的线程信息和镜像地址在下一次正常启动解析。报告带崩溃时 scope 哈希 customData，未绑定的报告不猜账号。
- 转换器仅输出固定技术字段：信号、异常名白名单、系统/应用版本、架构、故障线程和异常调用栈、镜像 basename/UUID/基址/偏移。不导出原始 reason、寄存器、路径、内存内容或用户参数。
- 私有存储独立文件，原子写、限额 32 条、七天过期、备份排除与数据保护。已导入报告按稳定 ID 去重；读取不删除，Dart 持久化后精准 ack。
- 与原有 Dart importer 共用 provider，首页恢复及日志准备前导入；日志准备的读取不得改变当前账号绑定。Android 协议兼容。
- 认证薄适配只插入观察点；独立通知观察器负责前后台及只读音频状态，独立串行写入器负责有界事件环。记录原回调线程和主线程派发后事件，不读取供应商私有对象，不改变 SDK 和音频控制。
- 进程 runId 与 Runner UUID 关联崩溃 schema 2 和时序 schema 1；最多 1024 栈帧及明确截断标记。时序每账号/进程 128 事件、32 文件/七天，队列 256 上限及缺失计数。读取快照身份稳定，ack 仅清对应水位，迟到回调保留原会话 scope。
- 原生 session 采用稳定诊断哈希，保留原业务格式；试听有独立观察身份。bind 在通道接收时直接入时序队列；崩溃 customData 只由主线程单一 owner 写入，后台 enable 后才发布 reporter 并采用最新绑定，不能等待存储 IO 才切换账号。

## Risks / Trade-offs

- 同进程 SDK 可能安装异常处理器 → 采集器只安装一次，不反复抢占处理器；必须在 iOS 真机认证初始化后验证可捕获性，未验收明确标记。
- OOM/系统强杀/初始化前不保证有报告 → 文档明确边界，不将上次未退出推断为崩溃。
- Windows 无 iOS 编译能力 → 定向 Dart 回放与原生测试源码可本地检查，Mac/Xcode 编译及实际认证需单独证据。
- 静态供应商框架符号可能缺失 → 保存完整镜像 UUID/偏移和对应构建 dSYM；需要供应商符号时明确说明。

## Migration Plan

新包安装后开始采集，不能追溯补采 10 月 19 日事故。保留原上传 API；回滚移除注册和本地 Pod，不改业务数据。
