## ADDED Requirements

### Requirement: 联系人列表必须按需构建并分离状态
联系人列表 MUST 按需创建可见联系人行，保留原生姓名号码语义、多号码规则与刷新；读取失败 MUST 显示重试，不同时伪装为成功空列表。

#### Scenario: 大列表和读取失败
- **WHEN** 展示大量联系人或本次读取失败
- **THEN** 行按需构建，已有列表可继续展示，错误与空结果分开呈现

### Requirement: 联系人权限必须提供显式设置入口
拒绝或有限授权 MUST 提供用户主动进入系统应用设置的入口，恢复前台 MUST 静默重读；授权范围变化后已不属于可读集合的详情 MUST 清除。

#### Scenario: 设置返回与有限授权变化
- **WHEN** 用户改变系统联系人授权并返回
- **THEN** 刷新实际可读集合，不自动重请求权限，不展示已失效选择或草稿

### Requirement: 联系人技能必须使用安装版本及独立生命周期
技能弹层 MUST 使用已有安装版本端口，独立加载联系人可用技能；加载或版本读取异常 MUST 可重试，不猜测安装版本。公共仓库明确返回内置目录时 MUST 沿用已有回退契约。

#### Scenario: 版本和目录加载
- **WHEN** 技能最低版本高于实际版本或加载失败
- **THEN** 不展示不可用技能；错误明确，可重试，销毁后的晚到结果不更新页面

### Requirement: 联系人一致性验收必须区分证据
联系人 MUST 共用原生有效页面的视觉及交互目标，设备权限、真实接口、系统电话与合成运行图 MUST 分别记录，不以测试或组件图冒充真实业务验收。

#### Scenario: 同状态运行对照
- **WHEN** 核对列表、详情、备注和技能弹层
- **THEN** 使用同合成数据/状态并记录运行条件、差异及未验证范围
