## ADDED Requirements

### Requirement: OCR 首次上传保存入口身份
系统 SHALL 在带有效入口 Skill 的首次 OCR 上传授权返回前保存同账号同会话的 active/pinned 绑定及选定联系人，且不得采用记忆或执行电话。

#### Scenario: 任意 Skill 的图片优先任务冷恢复
- **WHEN** 用户从首页或联系人 Skill 上传图片，退出再从任务列表恢复
- **THEN** 原 Skill 与联系人保持，列表采用首页发布标题，后续沿用该 Skill 原确认与外呼流程

#### Scenario: 重复上传与迟到旧上下文
- **WHEN** 请求重复、没有 Skill、原任务已接受输入或已有绑定
- **THEN** 不覆盖既有绑定、记忆授权、pending 和执行身份，未知或冲突绑定失败关闭，旧客户端仍可上传

### Requirement: OCR-only 不代表业务首轮已发送
客户端 SHALL 根据原会话事实判定业务初始化，不能因只有开场或 OCR 记录而抑制必要首轮入口参数。

#### Scenario: 上传后恢复继续输入
- **WHEN** 恢复账本只有开场与 OCR、尚无用户业务轮次
- **THEN** 恢复不执行工具；仍持有原入口时首次真实输入补传入口参数，任务列表恢复没有入口副本时沿用服务端持久绑定，不猜测 Skill 或重建联系人；后续普通轮次不重复初始化

### Requirement: 上传占位标题有确定兜底
系统 SHALL 在没有已成功生成标题时优先使用首次真实任务输入作为兜底，只有附件时保留原上传占位，不读取敏感 OCR 正文生成兜底。

#### Scenario: 生成失败或未生成
- **WHEN** 图片先上传、随后输入任务，且标题模型失败或未生成
- **THEN** 列表标题采用真实任务输入，不永久停留上传占位；成功生成标题保持不变
