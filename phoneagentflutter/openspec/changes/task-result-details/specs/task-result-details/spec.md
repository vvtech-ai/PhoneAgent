## ADDED Requirements

### Requirement: SDK采集必须等待实际释放后交还媒体
身份采集 MUST 共用正式音频占用，开始采集前停止可中断播放，采集期间 MUST NOT 被普通试听抢占。取消业务等待 MUST NOT 被当成设备资源释放。

#### Scenario: 采集结束或离页
- **WHEN** SDK返回、用户退出或账号失效
- **THEN** 作废旧业务结果，等待原生释放确认才交还租约；Android释放失败保留句柄供重试，iOS无公开取消接口时等待供应商回调与容器关闭
- **AND** 超时不伪造释放，晚到回调不能释放新租约或重新启动采集

### Requirement: 跨模块播放必须共享设备占用事实
系统 MUST 以同一进程级租约管理普通回执录音、翻译历史录音与克隆试听，MUST NOT 在旧端口未确认停止时启动第二播放。

#### Scenario: 新播放切换或停止失败
- **WHEN** 用户在其他模块开始播放
- **THEN** 等待可中断旧播放停止再启动新播放；停止失败/超时保留占用并允许显式重试，不假报释放或自动恢复旧播放
- **AND** 预加载不发起播放；不可中断媒体租约不能被普通播放抢占

#### Scenario: 账号与异步结果变化
- **WHEN** 用户退出、换账号或较新操作取代等待中的播放
- **THEN** 旧排队请求不得迟到启动，旧释放不得关闭新租约；账号切换必须等待旧实际释放，不能用新管理器绕过旧占用

### Requirement: 活动批量事件必须归属正确并隔离退出页面
系统 MUST 按固定v65聚合批量逐项进度，保留最终结果与未完整返回区别；MUST在活动批量退出后保留接收但禁止旧事件写入新页面或执行交互工具。

#### Scenario: 逐项进度与最终快照
- **WHEN** 同轮收到makeBatchCalls开始、带batchId/itemIndex/total的非空状态消息及最终批次快照
- **THEN** 按序号原位更新项目、总数不缩小，重拨保留尝试信息；最终快照替换进度，不新增重复卡或补造计费
- **AND** 断流保留已完成项目，只将运行项标为结果未完整返回；仅Done不能证明任务成功

#### Scenario: 活动期间退出和账号替换
- **WHEN** 用户退出活动批量统一页
- **THEN** 页面清理但账号级订阅接收到结束/错误，活动期间不提交新轮；后续事件不能触发旧页面、权限、外呼确认或污染新会话
- **AND** 账号更换立即关闭旧订阅，结束刷新任务列表读取；恢复依然读取持久历史且不自动重拨

### Requirement: 普通回执录音必须保持入口与按需语义
系统 MUST 按固定v65区分普通单路完整录音卡和批量紧凑播放按钮；普通播放源 MUST 在用户点击后加载，MUST NOT 把翻译历史自动预下载规则套到普通回执，也不能从没有摘要的接口虚构服务器校验信息。

#### Scenario: 普通与批量显隐
- **WHEN** 单路具有可见转写和metadata.callId，或批量具有callId且最后结算的connectedDurationMs大于0（无结算时仅需callId）
- **THEN** 显示相应完整或紧凑控件；缺条件不补造入口，批量不新增保存按钮

#### Scenario: 交互阶段演练
- **WHEN** 开发者进入明确MOCK的普通回执录音演练
- **THEN** 共用结果卡、控制器和控件，验证播放/暂停/重试/保存取消但不连接真实录音或账号；生产接口和媒体生命周期仍须独立实现验收

#### Scenario: 普通录音真实源
- **WHEN** 页面读取普通录音状态或用户点击播放/结束后重播
- **THEN** 元数据与播放源分离，元数据仅在处理中每2秒有界观察最多60秒；播放和结束后重播显式申请新token，暂停续播不重复申请
- **AND** 初始播放地址MUST属于当前API上下文下recording-content路径，不附加账号请求头；读取服务端可选sizeBytes/expiresAt但不伪造不存在的远端SHA256
- **AND** 更新的播放请求或宿主停止MUST作废较旧加载结果，不能让旧请求晚到自动播放；此核心验证不替代正式保存与双端系统媒体验收

### Requirement: 普通录音保存与宿主必须独立管理

系统 MUST 按普通录音契约管理保存与宿主，不套用翻译录音的预加载和缓存规则。

#### Scenario: 普通保存独立于播放
- **WHEN** 用户保存普通单路录音
- **THEN** Android先选择新文档再申请新播放源；iOS下载本次私有文件后导出副本；取消不报成功、失败只清本次输出
- **AND** MUST共享Dart下载和保存状态，保存失败不破坏播放，批量不新增保存；退出/换账号作废晚到结果，临时资产清理且不假造服务端SHA256

#### Scenario: 普通回执宿主
- **WHEN** 录音卡离屏、会话退后台或退出
- **THEN** 离屏只停止元数据观察，播放由会话宿主持有；退后台停止播放，退出/换账号关闭播放、元数据和本次保存
- **AND** Web生产页面明确系统能力边界，隔离MOCK不接真实账号或录音

### Requirement: 翻译历史录音必须共享可恢复的交互
系统 MUST 在有效录音详情载入后预加载但不自动播放，保留处理中/失败/重试、播放暂停、剩余时长和用户主动保存。录音错误 MUST 不影响字幕阅读，不新增进度拖动或真实呼叫。

#### Scenario: 授权或下载失败
- **WHEN** 录音尚在处理或请求失败
- **THEN** 只对明确RECORDING_NOT_READY按服务返回延迟有界等待；显式重试刷新详情与授权并清旧缓存，校验大小和SHA256后才交播放器
- **AND** 授权和账号请求头不传到外部签名下载地址，UI与日志不输出凭据

#### Scenario: 保存取消与离页
- **WHEN** 用户取消系统保存或退出历史页
- **THEN** 取消不显示保存成功，退出停止播放器和观察，晚到结果不进入新账号/页面
- **AND** Web隔离演练使用共享状态和控件但不读取真实文件、播放真实声音或修改账号

#### Scenario: 正式文件端口与续传
- **WHEN** Android/iOS历史页存在有效录音并读取缓存或网络文件
- **THEN** MUST以环境/API/账号/通话隔离，仅长度和SHA256均通过的文件交播放器；半文件按Range恢复，200覆盖旧半文件、416最多重试一次全量，错误206拒绝，签名URL不跟随重定向
- **AND** MUST只向系统导出本次已校验资产，用户取消不报成功，离页停止下载/播放器与导出等待；文件路径和凭据不进入UI或日志

### Requirement: 回执卡必须保留结构和独立交互状态
统一页 MUST 使用共享组件展示单路转写/结构化结果/有效计费及批量进度/逐项结果。批量每项MUST可独立展开有效转写，项目身份、状态或转写变化时重置折叠；MUST NOT 把结果返回数当成功数、把录音未接入伪装播放成功或新增执行按钮。

#### Scenario: 多项通话记录
- **WHEN** 用户展开其中一个批量项目
- **THEN** 只展开该项目的记录，收起/返回不改变其他项目或触发HTTP、外呼

#### Scenario: 结果更新和缺失字段
- **WHEN** 实时/历史投影更新回执或缺少积分/转写
- **THEN** 组件只显示实际字段，沿用既有状态归属与业务结论，不补造通话或计费数据

### Requirement: 历史详情必须保持已有来源边界
Flutter MUST 使用 Phone Agent 翻译历史详情接口读取字幕；普通无 session 任务沿用进入统一页行为。

#### Scenario: 翻译记录打开
- **WHEN** 用户点击 REALTIME_TRANSLATION 记录
- **THEN** 读取匹配 callId 的详情，展示原文和译文
- **AND** 不过滤 final=false 的有效内容，不触发通话或自动播放；真实录音端口接入后独立预加载，交互演练阶段不读取真实媒体

#### Scenario: 普通记录没有会话标识
- **WHEN** 普通任务没有 sessionId
- **THEN** 进入新统一对话，不新增旧独立结果页

### Requirement: 录音异常不得破坏可读历史
Flutter MUST 对录音元数据单独容错，不输出授权内容。

#### Scenario: 录音定位不完整
- **WHEN** 录音数据缺字段或无效
- **THEN** 保持字幕和基本信息显示，不伪装录音成功

#### Scenario: 请求晚到
- **WHEN** 用户已退出或账号已切换
- **THEN** 忽略旧结果，不更新其他账号或页面

### Requirement: 统一确认展示遵循服务端事实
统一页 MUST 共用实时和历史确认数据模型，并在对应工具被 rejected/policy_rejected 后移除该确认卡；MUST NOT 给只读确认卡新增执行按钮或在恢复历史时触发拨号。

#### Scenario: 实时确认随后持久化
- **WHEN** 同工具收到 MAKE_CALL_REQUEST/call_ready 和 TOOL_REQUESTED
- **THEN** 只显示一份确认，保留目标/电话/目的/摘要，普通 AI 文本不得吞掉卡片

#### Scenario: 批量确认摘要
- **WHEN** makeBatchCalls 包含多个有名字的收件人
- **THEN** 展示联系人摘要和人数，不补造脱敏电话，不误用单路电话行

### Requirement: 回执按呼叫尝试归属并可恢复
统一页 MUST 以 session 和 callAttemptId 聚合单路回执，区分同任务的多个尝试；MUST 保留服务端提供的结果字段、文本和有效计费摘要，不凭传输结束推导成功。

#### Scenario: 同一通话逐步结束
- **WHEN** 同一 attempt 依次收到 requested、started、terminal 和 outcome
- **THEN** 原位置的单个回执更新为最新权威状态，逐字稿和结果字段仍可查看

#### Scenario: 同任务重试与恢复
- **WHEN** 同 task 下存在两个 attempt 并重新打开历史
- **THEN** 两份回执保持各自归属和顺序，不混合电话、计费或结论，也不触发新的通话

### Requirement: 批量结果快照必须保留每项事实
统一页 MUST 按批次身份接入实时与持久快照，保留普通说明和各项状态/转写/结算；MUST 保留 task_completed 返回的失败批次明细，不因事件名字推导整批成功。

#### Scenario: 同批结果更新
- **WHEN** 同 batchId 先后收到运行与结束快照
- **THEN** 原位置更新为最新完整快照，保留兄弟批次，不把进度等同于成功率
- **AND** 实时终态不得被同身份的旧运行中快照降级，持久终态到达后仍取持久结果

#### Scenario: 积分门禁拒绝
- **WHEN** 所有项目 attemptCount 为 0 且服务端报告积分不足
- **THEN** 不展示已执行的批量结果，保留服务端通知，不拨号、不伪造扣费
