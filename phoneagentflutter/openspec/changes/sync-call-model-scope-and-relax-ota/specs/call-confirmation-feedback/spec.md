## ADDED Requirements
### Requirement: 确认外呼必须先回显并提供准备反馈
系统 MUST 在文字、语音或按钮明确确认后立即显示一次用户确认内容，并在原有准备等待期显示 AI 处理状态。准备期 MUST 允许取消或修改要求，不增加新的等待计时。实际下发前 MUST 再检查当前模型授权；失败可以重新确认，MUST NOT 伪造调用成功或推理内容。
#### Scenario: 用户确认后等待实际下发
- **WHEN** 用户明确确认当前有效通话卡片
- **THEN** 先显示用户确认消息和准备反馈，在原有1500毫秒后才按既有准入规则下发；服务端回显不得再生成一条重复确认消息
#### Scenario: 准备时取消或模型被撤权
- **WHEN** 等待期间用户取消或模型目录不再允许新呼叫
- **THEN** 不提交该呼叫，不改动真实在途通话，恢复可重试状态

### Requirement: 拨打结束后必须反馈等待权威结果的状态
系统 MUST 对照原生v1.6.0，在物理通话结束后返回对话并显示整理结果状态，直到权威结果或当前命令的真实思考/总结接替。旧命令的思考内容 MUST NOT 遮挡本次等待状态；结果文字和语音 MUST 沿既有事件与去重机制处理。
#### Scenario: 等待结果时仍有旧思考消息
- **WHEN** 当前通话已物理结束但权威结果尚未到达，历史消息中仍有处理中的旧思考
- **THEN** 显示本次整理状态，当前命令的真实思考到达时才由它接替；不提前宣称业务完成，不重复播报总结
