## ADDED Requirements

### Requirement: 物理通话终态必须继续观察业务结果
系统 MUST 将网络异常、积分不足、远端异常和多路通话结束产生的物理终态与业务结果分开处理。物理 hangup、SSE done、transport failure 或错误提示只能结束通话观察，不能单独被解释为业务成功；只要结果事实尚未确认，系统 MUST 保留会话/任务/通话尝试身份并进入有界的结果同步流程。
在有界观察期间，只有同身份可信业务结论才能结束结果等待并进入绿色完成或红色失败、未完成、执行异常终卡。仅有物理结束、处理结束或本地超时 MUST 保持未确认语义，不生成黄色结果终卡，也不得推断为绿色或红色业务终卡。

#### Scenario: 异常挂断后结果稍晚落库
- **WHEN** 通话已经进入异常物理终态，但当前历史读取尚未发现最终业务结果
- **THEN** 系统继续按同一 sessionId、taskId 或 callAttemptId 进行有界的历史/timeline/result 读取，并保持页面处于可解释的处理中状态
- **AND** 系统不得因为 hangup、SSE done 或 transport failure 直接显示业务成功

#### Scenario: 积分不足或网络异常明确产生业务失败
- **WHEN** 后续结果读取返回可识别的业务失败或积分不足事实
- **THEN** 系统合并该失败结果，停止结果等待并解除 loading
- **AND** 页面显示与该失败事实对应的状态，不要求用户重新进入会话才能看到

### Requirement: 结果到达必须原子解除会话和任务列表的旧状态
系统 MUST 在确认最终结果后先完成消息/结果合并，再使当前会话的 loading、思考中或未完成标记失效，并触发对应任务列表 provider 的一次刷新或失效。重复事件 MUST 幂等处理，晚到的物理终态不得覆盖已确认结果。

#### Scenario: 单路结果在挂断后到达
- **WHEN** 单路会话在物理终态后读取到最终结果
- **THEN** 当前会话显示结果并解除 loading，任务列表刷新为后台终态
- **AND** 同一结果重复到达不会生成重复消息或重复刷新循环

#### Scenario: 单路执行异常已返回结果
- **WHEN** 当前轮服务端结果 `status=EXECUTION_ERROR` 已到达，业务结果尚未证明成功或失败，且启动前异常可能尚无 `callAttemptId`
- **THEN** 当前结果终卡的技术失败状态对照 v66.0.3 显示“执行异常”，并显示本轮用户确认的服务端公开说明“本次任务已结束，结果处理异常”；不得显示黄色“结果确认中”卡或保持加载
- **AND** 提交账本恢复时仍有终卡；保留已有通话、账务与转写事实，非终态账务显示待核对，不将执行异常改写为未接通或零扣费

#### Scenario: 单路尚未注册 callId 时实时流失败
- **WHEN** 用户已确认单路拨打，SSE 在 `call_started` 前失败，服务端稍后提交无 callId 与 attemptId 的 `EXECUTION_ERROR` 终卡
- **THEN** 原会话按同一确认 command 自动有界读取账本，只接受该命令的已提交终卡并结束等待；其他命令的终卡不能结束当前观察
- **AND** 单次读取慢或失败不使等待无限延长；独立截止时间到达仍无可信终卡时，显示明确的未确认反馈并保留原身份供恢复补查，不重拨或伪造业务结果

#### Scenario: 单路确认请求收到未知 502/503 握手失败
- **WHEN** 单路确认请求在取得 callId 前收到 HTTP 502 或 503，且响应没有可核验的业务拒绝事实
- **THEN** 客户端保留原确认 command 和执行不确定性，按该身份只读补查已提交结果；不得把握手状态直接解释为未拨出、业务失败或可安全重拨
- **AND** 无 callId 的慢账本请求由独立五分钟截止限制；届时仍无可信结果须反馈未确认，迟到旧响应不得覆盖当前会话

#### Scenario: 已知 callId 的结果请求持续未返回
- **WHEN** 单路已取得 callId 并进入物理结束后的结果同步，但一次结果读取持续 pending
- **THEN** 独立五分钟截止到达时停止等待并反馈未确认，保留原 call/attempt 身份供后续只读补查
- **AND** 不因单次请求未返回而无限停留在等待态，也不重拨或伪造终态

#### Scenario: 多路批量结果在最后一路结束后到达
- **WHEN** 多路通话均已结束且批量结果回执可用
- **THEN** 批量结果卡、各路状态和任务列表在同一结果事实基础上更新
- **AND** 不因某一路 transport failure 或音频中断而继续显示无限加载

#### Scenario: 批量回执为待核对执行异常
- **WHEN** 后台提交同一 batchId 的批量回执，`status=PENDING` 且 `executionStatus=EXECUTION_ERROR`，部分通话或账务证据仍缺失
- **THEN** 当前会话以已提交回执替换旧的本地进行中卡；结果卡显示“执行异常”和“本次任务已结束，结果处理异常”，各路仍分别展示已知结果或待核对事实，并结束该批次的等待态

#### Scenario: 批次执行终态与运行中业务汇总并存
- **WHEN** 已提交批次回执为 `executionStatus=EXECUTION_ERROR`，业务汇总 `status` 和某条逐路 `status` 仍为 `RUNNING`
- **THEN** 执行终态优先关闭批次等待态，展示含“执行异常”和“本次任务已结束，结果处理异常”的结果卡；仍为 `RUNNING` 的逐路在卡上显示“待核对”，已有账务、字幕等事实仍按原身份展示
- **AND** 不把缺失证据补成成功、已结算或失败；客户端诊断记录进度请求开始、脱敏响应摘要或解析失败、历史同步、可见回执和页面是否仍在等待的关联字段

#### Scenario: 批次账本与逐路结果均无法读取
- **WHEN** 当前轮返回 `batchCallResult.executionStatus=EXECUTION_ERROR`，但 `items` 为空且 `batchId` 缺失
- **THEN** 当前页按 command 关联结果终卡，历史从提交事实恢复同一张卡，显示“执行异常”和“本次任务已结束，结果处理异常”，并结束等待；可见终卡允许任务已读回执
- **AND** 不显示虚构的 0 路失败、零扣费或逐路结论；普通缺身份或缺结果的回执仍不能替换在途进度

#### Scenario: 进度接口已返回提交回执而历史同步暂不可用
- **WHEN** 同批次进度接口返回正数结果序号和可核验的已提交批量回执，但独立历史同步失败
- **THEN** 当前会话直接显示该回执并结束等待，不继续停在旧进度卡
- **AND** 批次身份不匹配、缺少结果序号或回执仍含运行态时不得按最终结果展示

#### Scenario: 批量结果长期未提交
- **WHEN** 当前批次在有界补偿窗口结束时仍无可见的已提交结果
- **THEN** 客户端停止自动轮询，将临时进度显示为明确的“结果尚未确认”，在当前页面保留批次身份和发送门禁；重新进入会话时重新读取历史
- **AND** 仍以临时进度呈现已知逐路事实，不显示代表已提交终卡的“执行结果／结果回传”区域；不自动重拨，不把未确认的通话或账务状态伪造成成功或业务失败

#### Scenario: 批量截止时进度请求仍未返回
- **WHEN** 同一批次的进度或账本读取持续 pending，独立五分钟截止已经到达
- **THEN** 当前页立即结束等待并显示明确的未确认反馈，不等待该请求完成才启动下一次轮询或解除加载
- **AND** 迟到响应仍受原 batch、会话和代次校验；没有已提交结果时不得编造成功或失败

#### Scenario: 重拨准入被拒且未形成第二次电话
- **WHEN** 服务端先通知准备重拨，随后返回第二次尝试的准入失败及未拨出证据
- **THEN** 临时进度显示该路重拨未发起，物理尝试次数仍为一次，不把重拨准备状态当作已完成的第二次通话
- **AND** 其他在途和排队联系人的状态继续按各自证据更新

#### Scenario: 旧准入快照晚于物理进度到达
- **WHEN** 同一通话尝试已收到带版本的 SDK 振铃或接通进度，随后读到无 SDK 尝试事实的零版本 `ADMISSION` 快照
- **THEN** 客户端保留已收到的较强物理进度，不被准入快照降级

#### Scenario: 本机来电遮挡多路外呼后返回原会话
- **WHEN** 活跃批次的实时流中断，应用经历 `inactive`、`hidden` 或 `paused` 后回到前台，且原会话路由和账号仍有效
- **THEN** 当前页立即以原 sessionId、batchId 和 commandId 只读核对批次进度与账本；不重建会话、不重拨，也不等待退出重进
- **AND** 同一路 SDK 物理进度或已提交逐路事实可更新原卡；仅有准入或缺失物理事实的路保持待核，不将进度 HTTP 成功当作整批最终结果
- **AND** 同 batchId 的已提交回执到达后原位替换临时卡并撤销旧的连接中断提示；历史读取抛错时，已核验的进度回执仍可结束等待

#### Scenario: 批次观察已停止但原页仍留临时卡
- **WHEN** 有界批次观察已经停止，原会话仍显示同 batchId 的本地临时卡，应用从 `inactive`、`hidden` 或 `paused` 回到前台，且原会话路由和账号仍有效
- **THEN** 当前页以原 sessionId、batchId 和 commandId 只读同步账本，不因批次已非活动而跳过，也不重启进度轮询或重拨
- **AND** 同批次已提交的终态回执原位替换临时卡并撤销对应旧提示；尚无可核验回执时保留待核状态和发送门禁，不用空历史伪造完成

#### Scenario: 前台恢复期间旧响应迟到
- **WHEN** 用户重复回到前台，或恢复读取尚未结束时离开会话、切换账号或进入新一轮任务
- **THEN** 同一批次的只读读取不并发重放，旧 session、batch 或 generation 的响应不得覆盖当前消息和状态

#### Scenario: 来电未造成应用生命周期切换时终卡提交
- **WHEN** 多路通话仍在原页，实时流已断而服务端在后段补偿窗口提交了终卡
- **THEN** 客户端在有界观察窗口内继续以短间隔读取同一 batchId 的进度与账本，原位显示终卡并结束等待
- **AND** 不依赖用户切换应用，也不重拨或无限高频读取

#### Scenario: 断网恢复或被覆盖路由重新可见
- **WHEN** 原会话仍有待确认的单路或多路结果，设备网络从不可用变为可用，或应用恢复时原路由被覆盖、随后重新可见
- **THEN** 客户端以原 session、command、call/attempt 或 batch 身份发起一次只读补查，并复用进行中的同身份读取
- **AND** 页面即使错过此前的 `unavailable` 广播，只收到 `available` 事件，也须在当前路由和会话身份有效时执行一次只读补查
- **AND** 多个网络消费者不得相互抢占平台事件；旧账号、旧会话和已确认结果不得重新触发外呼或覆盖当前状态

#### Scenario: 单路观察窗口耗尽后恢复补查
- **WHEN** 单路物理结束后的有界结果同步已停止，原会话仍保留未确认结果，应用重新可见或网络恢复
- **THEN** 客户端用原 call/attempt 身份只读补查一次；读取到已提交结果时原位结束等待，读取失败时记录脱敏诊断并保留待确认
- **AND** 不重新启动完整轮询窗口，不提交新命令或再次拨号

#### Scenario: 旧单路结果未确认时收到新的拨号工具
- **WHEN** 已有物理闭合证据的单路通话结束有界结果观察，随后同会话收到新的有效拨号工具
- **THEN** 新确认卡可按新 tool 身份呈现；仅用户再次明确确认后才进入新拨号准入，旧 call/attempt 身份继续供前台只读补查
- **AND** 旧通话状态轮询停止，旧 callId 不得误绑定到新线路，旧结果迟到不得关闭新线路
- **WHEN** 旧确认请求尚无 callId 且是否执行仍未确认，或仅收到不足以证明物理闭合的 call_finished
- **THEN** 暂不呈现无法执行的新拨号确认卡，给出明确的待核提示，保留旧身份供只读补查，不自动重拨

#### Scenario: call_finished 先于可读状态到达
- **WHEN** 当前通话收到 call_finished，但状态接口随即读取失败
- **THEN** 已绑定 attempt 的客户端以该 attempt 启动有界的只读结果同步；结果仍须以已提交事实确认
- **AND** 若本地尚无 callId，即使事件内层结果带 callId/attemptId，也只按当前确认 command 读取账本；若本地仅有 callId、未绑定 attemptId，则匹配的 callId 可以启动只读补查，不把未知 attemptId 与 callId 强行比较
- **AND** call_finished 本身不证明物理闭合或业务成功，也不触发远端挂断

#### Scenario: 物理事实已存在但语义结果仅在最终账本提交
- **WHEN** 同一 attempt 已有 `CALL_REQUESTED`、`CALL_STARTED` 或 `CALL_COMPLETED`，没有 `CALL_OUTCOME_REPORTED`，但 `ASSISTANT_TURN_COMMITTED.callResult` 已提交同身份、明确的 `agentOutcome`，或已提交明确的 `status=UNCLEAR`／`EXECUTION_ERROR` 终态
- **THEN** 原页按已提交结果显示一张终卡并结束该 command 的结果观察，不继续只显示物理进行中或物理结束状态
- **AND** `resultCode` 只能在可信结论成立后补充业务细节，单独不足以结束结果观察；保留真实 callId、字幕和已确认账务；无本地 callId 时必须核对结果的 commandId，旧命令结果不得关闭当前线路

#### Scenario: 已提交完成状态仍缺业务结论
- **WHEN** 同一 attempt 只有物理结束事实与 `ASSISTANT_TURN_COMMITTED.callResult.status=COMPLETED`，且没有可信的 `CALL_OUTCOME_REPORTED`、明确的 `agentOutcome` 或明确技术异常
- **THEN** `COMPLETED` 仅证明该阶段结束；物理通话已结束且仍在观察时，当前页显示独立的黄色“正在确认通话结果”小提示，不生成绿色完成、红色失败或黄色“结果确认中／结果未确认”结果卡，也不因账本已提交而结束该结果观察
- **AND** 物理回执或该提交结果中即使有 `resultCode`，也不单凭它解除等待；有界窗口结束仍无可信结论时显示未确认的临时反馈并保留原身份供只读补查，后到的同身份可信业务结果再原位替换为相应终卡

#### Scenario: 已报告语义结果与最终账本结果并存
- **WHEN** 同一 attempt 同时已有 `CALL_OUTCOME_REPORTED` 和已提交的非运行 `ASSISTANT_TURN_COMMITTED.callResult`，但本地仍没有 callId
- **THEN** 终卡保留已报告语义 outcome，同时从同 sessionId、callAttemptId 的已提交结果补齐 `headline`、`detail`、`resultCode`、`fields` 和已确认账务；当前 command 的已提交结果可结束无 callId 的本地观察
- **AND** 补齐在原卡完成，不因已报告事件存在而丢弃最终结果字段；物理、语义报告和最终提交事件的 `commandId` 不要求相等，不同 session 或 attempt 的结果不得关闭当前线路、污染终卡或取消当前命令的结果读回

#### Scenario: 单路订餐已报告结果未获明确确认
- **WHEN** 单路订餐的 `CALL_OUTCOME_REPORTED` 已报告 `UNCLEAR`，任务状态为 `INCOMPLETE`，随后同 sessionId、callAttemptId 提交非运行的 `ASSISTANT_TURN_COMMITTED.callResult`
- **THEN** 当前页在已有可信报告到达时显示“任务未完成／未完成”的已结束终卡，后续提交结果在原卡补齐业务字段、简短业务说明与已确认账务；实时与账本恢复一致，不显示黄色“结果确认中／结果未确认”或继续 loading
- **AND** 原结果保留“通话未获明确订位确认、短信发送未确认”等事实供状态判定与诊断，任务卡不展开长篇原始原因、技术码或诊断正文；不推断预订成功、短信已发送、电话未拨出或零扣费；尚未取得可信结果时沿用中间等待文字，不生成结果卡

#### Scenario: 其他单路已有未明确的业务报告
- **WHEN** 同身份单路电话已收到可信的 `CALL_OUTCOME_REPORTED.outcome=UNCLEAR`，或非运行最终 `callResult.status=UNCLEAR`／`agentOutcome=UNCLEAR`
- **THEN** 当前页与历史显示已结束终卡：任务型标题“任务未完成”，普通电话标题“通话未完成”，状态均为“未完成”；不显示黄色“结果确认中／结果未确认”或继续 loading
- **AND** 同身份结果观察同步闭合并保留原始不明确原因、物理通话与已确认账务事实；仅有物理完成或 `call_finished` 而没有可信业务报告时，按 v66.0.3 显示独立的黄色“正在确认通话结果”小提示，不生成黄色结果终卡，物理回执的 `resultCode` 单独不足以结束等待，不推断成功、未拨出或零扣费
- **AND** 物理完成前后的 `TOOL_RESULT_RECORDED.result.metadata` 若暂含 outcome 或 `_ledgerOutcomeSource` 字符串，不得单凭该工具元数据结束等待或替代账本报告；同通话旧实时 `UNCLEAR` 不得覆盖随后提交的 SUCCESS／FAILED 结论

#### Scenario: 任务终卡保留简短业务原因并隔离内部诊断
- **WHEN** 任务型单路结果已可信判定为失败、未完成或执行异常，或执行异常回执暂缺任务字段；原结果的 `agentReason`、`resultReason`、`detail` 或原因类结构化字段可能包含 `terminationCause=SYSTEM_STOP` 等技术码或长篇诊断
- **THEN** 当前页、同会话恢复和只读详情中的任务卡保留简短业务 `headline`、业务字段、正常的简短原因、状态与已确认账务，不直接展示长篇原始原因、技术码或诊断正文
- **AND** 保留原结果事实供状态判定和内部诊断，不改写通话转写、账务、身份或业务 outcome；成功任务和非任务普通电话失败维持原有展示规则

### Requirement: 终态同步必须可恢复且有明确观测字段
系统 MUST 对终态同步设置可配置的次数或时间上限；达到上限仍无结果时 MUST 停止轮询并保留可恢复的待同步状态或明确的待确认提示。每次终态判定和同步尝试 MUST 记录稳定标识、阶段、结果类型和结束原因，不得记录对话正文、令牌或其他敏感凭据。

#### Scenario: 握手诊断与日志级别
- **WHEN** Agent 流握手失败或成功，诊断日志由 DEBUG、INFO、WARN 或 ERROR 构建配置控制
- **THEN** 可记录受限的 HTTP 状态码及阶段、耗时和稳定身份；常规 INFO 保留里程碑和失败，细粒度事件仅在 DEBUG 级别保留
- **AND** 不记录响应正文、请求 URL、号码、令牌或凭据；当前本地回归已覆盖状态码，目标设备日志仍须另验

#### Scenario: 结果在本轮同步窗口内未出现
- **WHEN** 有界同步达到上限且没有最终结果
- **THEN** 页面退出无限 loading，保留可重试/重新进入后恢复的状态，并记录未确认原因
- **AND** 后续页面恢复或网络恢复可以使用同一身份再次同步

#### Scenario: 结果已确认后收到晚到失败事件
- **WHEN** 已确认最终结果后收到旧 generation 的 hangup、网络失败或错误提示
- **THEN** 系统忽略该旧事件对结果状态的覆盖，仅保留必要诊断信息
