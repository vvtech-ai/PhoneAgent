## ADDED Requirements

### Requirement: 订单空表与真实读取状态
客户端 MUST 在成功读取空订单时保留类型、日期、金额、支付渠道、状态、操作表头，居中显示暂无更多数据；加载和失败不得伪装为空成功。
#### Scenario: 空列表
- **WHEN** 订单成功返回空列表
- **THEN** 展示六列表头和暂无更多数据，无横滑提示和翻页箭头

### Requirement: 当前会员摘要
客户端 MUST 使用服务端当前权益字段在余额卡下展示等级、包月/包季/包年和斜线日期到期提示，不依据所选待购买商品计算当前权益。
#### Scenario: 切换待购买商品
- **WHEN** 当前为初级包月且用户选择其他等级周期
- **THEN** 摘要仍展示当前初级包月及服务端到期日

### Requirement: 会员购买视觉与确认
客户端 MUST 按指定d82d363参考统一权益、积分包、周期卡及确认弹窗视觉，协议可在会员购买按钮下主动勾选，支付确认必须仍要求明确同意和服务端报价；不得虚构渠道或演示权益。
#### Scenario: 未同意或取消
- **WHEN** 用户未同意协议或取消支付确认
- **THEN** 不执行购买且保留现有重复提交和报价身份保护

### Requirement: 页面协议与真实会员模型
会员购买 MUST 仅在会员页显示协议勾选；未勾选 MUST 停止报价与下单，支付确认中 MUST NOT 再显示协议勾选。会员专属模型 MUST 按所选已发布权益与免费档差异展示真实模型名称，目录读取失败后下拉刷新 MUST 重试。

#### Scenario: 未同意协议点击购买
- **WHEN** 用户未勾选页面协议而点击购买会员
- **THEN** 页面提示同意协议，不请求报价，不创建订单，不弹支付确认

### Requirement: 真实结果与精简入口
成功结果 MUST 显示已购买、当前权益、本次积分及可用积分；当前权益和可用积分 MUST 在履约成功后新读，不能从购买前余额或报价推算。实际升级 MUST 保留原套餐权益暂停保留说明。客服 MUST 仅在底部显示已发布邮箱。

#### Scenario: 排队购买成功
- **WHEN** 新购套餐尚未生效
- **THEN** 当前权益显示接口返回的活动套餐，本次积分显示暂未发放，余额使用新查询结果

### Requirement: 生效规则入口按等级显示
初级与中级确认弹窗 MUST 显示默认收起的查看生效规则，按报价区分立即及排队说明。高级 MUST NOT 显示该入口，包括排队续购。

#### Scenario: 高级排队续购
- **WHEN** 目标等级为高级且等待前序套餐
- **THEN** 继续显示预计生效与首期积分，但不显示查看生效规则入口

### Requirement: 积分包确认
积分包付款前 MUST 展示基础积分、赠送积分、到账总积分、实际渠道和服务端报价；iOS继续显示系统本地化价格。确认前 MUST NOT 创建订单。

#### Scenario: 积分包取消确认
- **WHEN** 用户关闭积分包确认弹窗
- **THEN** 不创建订单，不调用原生支付

### Requirement: 积分流水位置与积分购买视觉
积分流水 MUST 保留在现有余额行右侧，购买积分 MUST 保留在余额卡右上角；两者保持独立点击行为。卡片、积分包及确认弹窗 MUST 按参考字号、间距、圆角、颜色对齐，并支持大字体滚动。
#### Scenario: 点击积分流水
- **WHEN** 用户点击余额旁积分流水
- **THEN** 打开现有流水页，不进入购买流程

### Requirement: 已批准的等级介绍
中级 MUST 显示高峰优先线路及高峰时段优先分配通话线路；高级 MUST 显示高峰极速优先线路、高级会员极速优先、新模型抢先体验及高级会员专享。客户端 MUST NOT 展示专属呼叫号码；固定介绍不能替代实际权限判断。
#### Scenario: 切换高级
- **WHEN** 用户选择高级会员
- **THEN** 展示高级对应介绍，价格、积分和模型仍使用发布配置

### Requirement: 订单说明与发票状态
订单页 MUST 显示暂不支持自助退款说明及已配置客服邮箱；已开票使用蓝色、开票中使用棕黄色。发票状态 MUST 读取已有查询接口，查询失败不得捏造开票成功。
#### Scenario: 开票正在处理
- **WHEN** 对应订单发票状态为 INVOICING
- **THEN** 操作列显示棕黄色开票中，不重复发起申请
