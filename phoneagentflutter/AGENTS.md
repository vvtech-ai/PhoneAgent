# PhoneAgent Flutter 项目研发规范

## iOS 原生崩溃诊断约束

- 原生采集独立于认证、跟读、克隆和音频租约；只安装一次处理器，不随业务重试抢占，不用异常捕获冒充进程崩溃恢复。
- 可捕获报告在重启后自动进入既有日志上传，按崩溃时账号隔离，持久化后确认删除；导出仅保留白名单技术字段，不含认证内容、异常原文或原始内存。
- 原生认证时序采用独立观察器和有界存储，关联进程、构建 UUID、采集会话、实例及线程；记录丢弃与写入失败。旧快照确认不得删除新事件，迟到回调不得跨账号。诊断不 swizzle 供应商、不改音频、不阻塞业务；异步尾部丢失与符号缺失如实说明。完整合同见 [iOS 原生诊断](docs/engineering/IOS_NATIVE_CRASH_DIAGNOSTICS.md)。
- iOS 原生变更必须取得 Mac 编译与真机验证证据；Dart 测试不能代替处理器共存、SDK 正常流程和崩溃重启回放。构建保留匹配 UUID 的符号文件，不把同版本号当作同一二进制。
- 认证 SDK 升级独立评估并保留回退基线；官方“崩溃修复”发布说明不能代替本项目故障栈与回归证明。无报告不证明未崩溃，系统强杀和初始化前故障应如实说明采集边界。

规则版本：task-orchestration-v1.10。用户于 2026-10-21 确认；完整规则直接纳入 Java、Flutter、Web 各仓根部 AGENTS。v1.10 将无号例外收紧为明确指定且唯一命中的单一门店，品牌多门店候选也过滤无号；保留 v1.9 的号码资格和指定店名基础规则；保留 v1.8 将餐厅保存询问恢复为客户端按账号一次，使用已有记忆仍按任务确认；保留 v1.7 的普通业务回答与记忆选择来源隔离、单多条展示和同任务恢复回归；保留 v1.6 的候选完整性、管理结果连续性、任务有效模型和日志安装版本来源；保留已有评分逻辑、入口、思考锚点、TTS 连接和确认结果流程；本节独立生效，不依赖父工作区、相邻仓库、个人盘符或另行安装研发 Skill，历史相反条款不再作为当前行为依据。

### 规则来源与修改门禁

- 业务基线为重构前 Android 与后端 `test/v66.0.3@a0bedb12`；原生 App `feature/test_v1.6.0@8f235920` 用于差异对照。新任务先核对当前分支、HEAD、未提交内容及实际运行构建，不自动回退旧提交。
- 已批准例外：保留 1.6.0 每次成功切换模型后的独立反馈；冷启动采用完整有效缓存 / 经确认随包入口快照，后台新配置下次进入生效；道歉使用专用 Consent，普通 Skill 使用其普通或联系人专用开场。
- 修改前必须列出：所属仓库 / 层 / 状态 owner、受影响入口、相关接口与身份、将保留的规则、受影响回放编号、文件职责与验证范围。先定位事实，不凭“可能是缓存 / 时序 / 模型”直接改行为。
- 当前源码与规则不一致时，源码说明实际现状，规则说明已确认目标。先登记偏差和复现证据；不得为了迁就现状、一个测试或一张截图擅自改掉已批准规则。
- **修复必须保持既有不变量。** 禁止通过删除历史正文、放宽确认身份、增加全局去重 / 重排、改用任意默认模型、取消权益检查或把未知状态改成功来消除表面症状。测试失败先分析新旧期望，不为了变绿删除断言或回滚其他已验收能力。
- 改变已批准行为必须先有明确用户决策，再更新 OpenSpec、相关规则和验收场景；普通 Bug 修复沿用已有合同，不额外发明审批步骤。每项差异都须说明为何保持或为何获准改变。
- 三端本标记区域必须完整、同版本、同内容。跨端规则变化须同步相关仓库并在交付中列明对应提交；未同步不得声称三端一致。只改本端实现或端内职责不修改共享区域。不得只在个人工作区、旁系文档或日期备注里改规则。
- 详细源码对照与历史证据可另放版本化文档，但本文件必须保留完整入口、顺序、生命周期和验收要求。归档与旧分支只供追溯，不反向覆盖当前规范。

### 完整入口与时间线

#### 所有正式任务入口

| 入口 | 身份与开场 | 恢复 / 执行边界 |
| --- | --- | --- |
| 首页卡片新建 | 新 session；冻结一致版本卡片、Skill 和开场；道歉用专用 Consent | 新建不等于拨号，仍需信息收集与当前确认 |
| 联系人详情 / 联系人 Skill 选择 | 新 session；冻结用户选中的姓名、目标号码、Skill 和对应版本的 `selectedContactOpening`；模板按既有规则替换 `{contactName}` | 普通 Skill 优先联系人专用模板；模板缺失沿用已验证 v66 规则，再使用同快照普通开场。空姓名不编造称呼；道歉仍走专用 Consent。首个有效命令携带 selectedContact，上下文不能被后台刷新 / 旧弹层回调改写 |
| 任务列表可恢复会话 | 复用记录的 session / task / attempt，通过 `restore: true` 读取账本；不创建新开场 | 进行中与已结束会话均按真实状态恢复，不只按列表文案猜测；只恢复有效 pending，旧卡不自动执行 |
| 任务列表通话 / 旧任务详情 | 使用原 task / call / batch 锚点，结果与评分对应原任务，不新建会话补缺 | 无账本时显示真实已有详情，不编造对话、pending 或自动继续；显式新建另一个任务时才创建新身份 |

联系人普通系统拨号与翻译技能继续使用各自已存在的拨号 / 翻译路径，不因本合同变成任务 Agent。联系人姓名和号码的预填沿用既有契约；它们的授权与执行边界不被绕过。任务列表的翻译记录也继续走翻译历史路径。

同一任务经实时会话、列表恢复或详情进入，已提交业务事实、相对顺序、确认失活、媒体身份、模型评价和任务评分必须一致。差异只能来自明确标记的未提交 overlay 或真实迟到补全；不能靠重新进页多查一次才让实时页完整。详情保持只读；用户明确继续任务时，再校验原身份与当前 pending。

任务列表已读按原任务锚点和既有确认规则处理；读取 / 已读不得改变完成状态、生成评分资格或执行电话。接口失败必须保留失败语义，不能以空历史、伪造新任务或自动改走其他入口掩盖。

#### 客户端与后端阶段

| 阶段 | 客户端 | 后端 / 事实边界 |
| --- | --- | --- |
| 首页启动 | 有效缓存先用；首次无缓存用经确认的完整随包快照。图片、模型、权益等并行更新 | 发布卡片、Skill 与 opening 的一致配置；不以缓存授予权限 |
| 点击任务 | 冻结本次 Skill、开场来源与配置版本；立即展示开场，播报按用户设置与真实音频条件执行 | 后续请求按当前权限和规则校验 |
| 首次输入 | 追加用户消息，为本次输入创建独立身份 | 接受并记录用户轮次，识别 / 加载对应 Skill |
| 思考与工具 | 每轮一张思考卡；同工具原位更新；重复轨迹按身份收起 | 提交工具意图，执行并记录结果；等待用户的工具不被当作已完成 |
| 补问与选择 | 原提问 → 旧卡 → 用户回显 → 后续回复 / 新卡；旧卡保持选中且失活 | 验证当前 pending 身份和回答，继续同一任务链 |
| 拨打确认 | 任务确认卡 → Agent 确认提示 → 用户确认；确认后原提示仍保留 | 核对当前工具、确认内容和准入，取得确认后才执行 |
| 通话执行 | 区分等待接通、物理通话、整理结果；字幕和进度属于对应 attempt | SSE 编排、SDK 准入账务、Netty 模型媒体、Phone SIP 各自负责 |
| 通话结束 | 先展示已有可信结果，迟到字段原位补齐 | 物理结束、账务、最终字幕、语义结论分别可观察 |
| 结果区域 | 通话文字 → 有效录音入口 → 任务结果 → 模型点赞评价 → 任务评分 → Agent 结果说明 | 提供对应身份的结果、评价与评分资格 |
| 评分晚就绪 | 在原位置补齐；不要求退出重进，不阻塞正文或播报 | 区分暂未就绪、明确不符合、查询失败；资格与奖励由后端决定 |
| 历史恢复 | 从已提交账本重建；恢复有效 pending，不自动拨号或重播 | 提供有序、可重复读取的同会话事实 |

这是位置与因果约束，不要求所有网络事件串行到达。评分、录音等可选区域未就绪时不占用虚假内容，不阻塞已有结果；就绪后插入所属区域，不移动到下一轮。没有对话、录音或评分资格时不伪造相应内容。

```text
用户输入 → 接受轮次 → Skill / 思考 / 工具 → 补问或确认 → 用户确认
                                                       ↓
                       准入 → 拨号 → 物理通话 → 结束与结果补全
                                                       ↓
              字幕 / 录音 → 结果 → 模型评价 / 评分 → Agent 说明
                       同身份的后续事实只更新所属位置
```

`USER_TURN_ACCEPTED`、`TOOL_REQUESTED`、`TOOL_RESULT_RECORDED`、`ASSISTANT_TURN_COMMITTED` 及运行事实负责恢复；thinking、工具进度、`done` 等负责实时生命周期。`timeline_committed` 是提交事实的传输载体，`streamSeq` 不替代账本 sequence。时间戳用于诊断耗时，不用全局时间排序改写本地交互顺序。

### 消息、卡片、结果与语音的不变量

1. **一次事实或操作一个身份。** 组合使用账号 / session、event / sequence、command / turn、tool / attempt 及本地交互代次。模型 ID、卡片类型和文案不能单独代表一次操作。A→B→A 各有新身份；同一次操作重复回调只应用一次，旧代次不得覆盖当前状态。
2. **同身份更新保持首次位置。** 实时与账本副本协调为一份；必须确认同一事实，不能因同 command 就吞掉独立正文。同文案跨轮、跨工具保留。拒绝按全局文本指纹或网络返回时间重排。
3. **业务正文不按进度生命周期删除。** 提问、确认提示、回答和结果说明不能随 `done`、拨号开始、thinking 结束或 toolComplete 批量清空。只清对应身份的临时进度；无匹配权威事实时不得丢弃已显示业务内容。
4. **失活与删除分离。** 旧选项保留内容、选中样式和首次位置，仅最新合法 pending 卡可操作。确认动作同时校验工具身份、内容与代次；重建、切模和迟到事件不能复活旧卡。历史已记录提示仍可回看，不因此重新生成可执行确认。
5. **一轮一张思考卡，结构卡只抑制重复表示。** 思考遵循 append / start 语义并保留结束内容；真实思考与占位卡互斥。showOptions、确认、结果和文件等专用展示只覆盖同身份重复轨迹，不能吞业务正文；普通进度型工具结束可收起。 思考必须保留所属轮次的位置锚点；本轮没有可展示 assistant 正文时仍依托本轮输入或下一已知轮次定位，不能退到整个会话末尾。不同轮次各有身份，不因结果补查合并成一张，也不靠删除内容隐藏错序。
6. **结果、模型评价、任务评分独立就绪。** 首次可信终态与后续结果补全触发所属目标的资格核对；失败不是永久无资格，不用无限轮询替代合同。明确不符合时不造评分卡；已提交只读、同幂等提交不重复奖励，批量资格不能由某一路提前完成冒充整批终态。
7. **文字和 TTS 分离。** 开场、补问、确认提示和结果说明各按自身身份取得一次有效播报资格。思考、工具参数和历史不自动播报。中断 / 静音不删文字，旧代次音频失效；失败不能报告已播放，音色 / 模型切换保留用户选择且停止旧播放。实际音频可用性不由图片或会员展示加载决定。 播报按业务依赖调度：确认提示阶段按播报设置完成后才启动所属自动倒计时，静音时不等待音频，结果说明等待所属通话音频门禁释放，不等待评分或装饰加载。入队、合成与播放完成分别记录；失败或过期不能提前消耗后续消息资格。用户打断取消当前播放，不阻塞后续新消息；断流或补全时核对仍有效且未播放的内容，禁止无界重试和旧音频补播。 健康 TTS 连接由当前账号与任务会话持有，允许同配置跨回复复用及提前握手；预连接不合成、不播报、不授予业务权限。单次合成、PCM 播放与物理连接分开管理，完成一条回复不无条件销毁健康连接。空闲 ready / pong 和连接心跳不依赖当前是否正在合成；前后台、账号、任务、音色 / 模型配置、配置有效期及网络变化按各自边界失效。长期空闲有界回收，活动合成被打断时隔离旧音频，旧租约迟到释放不得关闭新轮连接。恢复仅在安全且未交付音频的范围内有限重试，不以无限长连、调低播放缓冲或缩短超时冒充供应商故障已解决。
8. **入口是完整且版本一致的快照。** 卡片、Skill 与开场整体校验，优先最近有效缓存，无缓存用经确认随包快照；明确无开场的入口才允许空值。后台更新供下次进入，不能改写已打开会话或重复开场。道歉使用专用 Consent；普通 Skill 使用快照中的配置 opening。
9. **启动成本由系统吸收。** 不增加常规任务内加载重试或等待会员展示的整页门禁。有效配置先发布，缓存写回、标语轮换和图片不阻塞；预检动画不作为业务就绪凭据。模型、网络、音色或准入的真实异常仍如实反馈；缓存不承诺权益有效或电话已可执行。冷缓存立即展示与弱网立即可播语音不是同一承诺。
10. **App Skill 与研发 Skill 各守边界。** App Skill 由后端 registry / activateSkill 和置顶范围约束；不能通过加载其他 Skill 绕开确认或权限。研发使用适用的 Superpowers：排查用 systematic-debugging，行为设计先明确，修复先重现再回归，交付用 verification-before-completion。技能须实际读取，不凭名称声称加载；同方向两次失败后按 stuck-debugging-reset 重建问题模型，不继续叠补丁。

11. **临时状态统一归属，停止进度连续展示。** 取消中、等待终态、整理结果、短暂异常和中断的运行反馈不得追加为任务对话正文、工具消息或持久历史；同一时刻由当前操作身份协调顶部播报 / 运行状态。置灰、停止中或已结束的按钮不重复发请求，也不因重复点击产生提示。真实失败给出简洁可理解的当前状态及适用操作；终态、恢复、离开或账号切换后撤销对应过渡状态，不覆盖最终结果正文。业务补问、确认提示和结果说明仍按真实身份保留；临时状态不得默认触发 TTS。 单路与多路确认停止后立即禁用底部停止按钮，保持原蓝色按钮样式；原思考卡位置只保留一张临时“任务处理进度”，原位衔接停止、等待结束与整理结果，不等待模型事件才反馈，不消失后追加到结果后。首轮同步耗尽仍未得到可信结果时保持禁用，顶部只读同步与明确失败重试分开；原有有界恢复及真实失败出口保留。进度不进入账本或 TTS，真实思考与正文不删除，结果可展示后恢复既有输入或播报控制，不等待评分或录音。

12. **记忆检索、使用和写入分别管理。** 需要既有信息时，按当前账号、开关、绑定 Skill、作用域和相关性读取候选；不得检索或采用其他 Skill 的专属记忆，ALL 仅按用户设置的有效通用范围参与；当前任务明确输入优先。候选首次采用前须向用户展示拟用信息并询问本任务是否使用，只有明确同意才进入已采纳事实。自由语音和文本按整句语义判断，不依赖固定说法；账号、Skill、候选版本、用途与问题身份由程序校验。同一任务同一内容版本及用途不重复问，新任务重新确认，历史恢复只消费已提交决定。不同意、不明确、疑问、改用本次信息或判断失败时，停止本任务的主动记忆询问，按原流程请用户提供本次信息；候选变化也不能自动重启询问。用户随后主动要求从记忆获取或采用刚才的信息时，允许明确改变决定：仅对当前 Skill 中已展示、版本与用途仍一致且指向明确的候选重新采纳；未展示、变更或指向不明时只补必要的当前候选确认，不能笼统解禁全部记忆。内容 / 用途 / 范围变化、关闭、删除或账号切换使相关授权失效；手动关联 Skill、过去任务同意和保存授权均不代替本次采用授权。未采用内容不得因检索或保存判重被注入模型、执行草稿或工具参数。明确要求记住、纠正或删除时沿用既有写入确认并在成功后更新状态；保存、使用和拨打确认各自独立。无记忆时不增加使用确认，保存询问按下述独立规则处理；历史恢复不重播、不执行旧确认。

    记忆范围匹配不等于本次相关：普通任务通过现有 Agent 工具在确有缺失信息时按 query / purpose 查询，不能每轮在主模型之前把全部范围候选强制问一遍。主任务只接收无正文的可用状态；独立候选分析只处理当前绑定 Skill 的必要候选。自然选择“姓潘的 / 姓黄的 / 第二个 / 尾号”等须返回并核验明确候选身份，只授权选中项，不把其他候选一并采用。候选内容不明确时仅补必要选择；用户已完整提供本次信息时直接继续。

    首轮与后续轮次使用相同的实时账号 / Skill 记忆状态，不能依赖进入设置页、第二次任务或客户端缓存热身。主模型已经准备补问缺失资料且跳过检索时，公共工具规范层对当前命令至多进行一次相关性补核：只在有候选、未停止主动询问、非管理 / 保存确认时检查，相关且未决定才转既有使用确认。无关、不可用、用户已提供完整资料或已采纳时保留原流程；补核本身不授权采用、不自动拨号，普通正文不额外分类。

    使用已有记忆仍按任务确认；只有餐厅新联系人保存询问按客户端账号只问一次。保存询问实际展示后持久记录账号标记，拒绝、忽略或不明确均不在后续任务主动再问；服务端仍保留当前任务及账本的已询问事实用于恢复。客户端首轮等待当前账号标记读取，不用未就绪默认值代替；无持久记录为未问，清缓存不等于清除应用数据，清除数据后的行为以实际记录为准。餐厅门店已选、新预订人姓名和完整号码由用户提供、记忆已开启、完整同内容不存在且账号与当前任务均未问时，拨打确认前必须询问保存；模型漏问时由独立规则补到原 askUser 流程，分轮提供资料也须覆盖。不可用、已有同内容、未开启、其他 Skill 或资料不全不新增保存门禁。标记只控制主动保存询问，不是使用或写入授权；用户后来主动要求保存或更新仍按原写入授权处理，保存同意不替代采用或拨打确认。

    普通业务卡的回答必须绑定当前命令与源工具身份；选择餐厅、联系人或其他业务选项的“第几个”不能被解释成记忆候选序号。文本、语音、选项按钮及恢复后的合法 pending 回答采用相同边界。普通来源先完成全部相关性核对，不返回采用 ID；用户本轮明确主动要求从记忆取用时，仍允许通过既有语义选择和当前版本门禁改变原决定。选择阶段保留原候选展示顺序，再核验所选身份属于相关集合，不能先过滤后使序号错位。当前命令已知但源卡被裁剪时不猜测采用；旧命令来源不得跨轮生效。单条记忆不加编号或“选择其中一条”，多条按稳定展示顺序编号。

    相关候选检索与采用选择是两条合同。候选分析必须逐项判断当前范围中条目与 query / purpose 的相关性；同一用途有多位可用联系人而用户未指定其中一位时，完整展示相关备选，不能只取第一位、最佳一位或把未选中等同于无关。采用仍只授权用户明确选中的当前版本，不因补齐数量纳入无关用途、其他 Skill 或失效条目。覆盖缺项、重复或未知身份的模型输出不得视为完整检索；诊断只记录数量、状态和身份关联，不记录候选正文。

    主动召回不受餐厅尚未选定的门禁阻断，普通搜索选店与后续联系人收集顺序保持。关闭、Skill 停用、无条目、无匹配、未采用和查询失败须明确区分；不可用结果不能伪装为 askUser 或空问题，不显示或播报“再确认几件事”，同轮不得对同一无效召回反复调用至迭代上限。拒绝或不明确后转正常缺字段补问，保留用户已提供信息，不把整个任务重新收集一遍。

    记忆管理定位独立于任务使用：明确修改、删除或查询管理目标时通过当前 Skill 的只读管理候选与版本确认目标，不要求先同意本次使用，也不要求用户背诵整条原正文或提供内部 ID。自然管理意图与普通使用、否定、引用和咨询由语义判断区分；管理查询不授予采用或写入。写入时核验当前账号、Skill、目标版本和明确管理授权；冲突不猜测覆盖。撤销旧采用来源不得过滤本次用户回答，实时、同步与恢复均保留明确输入的独立来源。

13. **保存判重不依赖使用授权。** 后端在当前账号与绑定 Skill 范围比较用户本次明确提供的信息和已有记录，只向模型暴露必要的匹配状态，不泄露未采用正文。已有同一联系人且完整姓名 / 号码一致时，不再次询问保存、不重复新增；同一写入重复投递保持幂等。信息不同不等于允许覆盖；明确纠正同一条记录须取得相应更新授权，新联系人沿用新增确认；缺少字段、解析不明或多条冲突时保留正常澄清，不能猜测匹配。此判重不能把他人、其他 Skill 或不同用途的记录混为一条。

14. **确认提示与记忆操作结果使用统一持久事实。** 单通确认卡及其固定提示属于同一工具展示合同，实时、补账本、任务列表恢复和旧账本兼容均按稳定子身份显示“卡片 → 原提示 → 用户确认”，已确认后原提示仍可回看。不得只在本地生成临时提示，或让历史恢复另造可执行确认；恢复不播报、不启动倒计时、不拨号。记忆关闭时的未保存说明和成功文案纠正必须在提交事实前生效，实时与历史不能相反；必要业务结果与取消中等临时运行状态分开。补账本不移动已显示说明，不按全局文案去重；无效内部问题仅留诊断。设置页安全展示容量、超长、目标失效及停用 Skill 等业务拒绝，网络失败仍保留适用重试；同一 ADD 操作响应丢失后重试复用稳定操作身份，不重复新增、不覆盖，不同操作各有新身份。容量按服务端 Unicode 码点和条数约束校验，失败不伪装成功。

记忆管理中的可公开操作结果与未采用候选正文分别投影。当前命令的成功、具体业务拒绝及不可用 / 无匹配状态必须可供后续说明，不能统一替换成内部隐藏标记而造成重复 ADD 或误报；内部隔离说明不进入用户对话和 TTS。管理候选正文只对当前合法管理上下文开放，命令身份不能仅由相同文案判断。保存确认须包含本次真实输入及 askUser 回答；保存授权不代替本任务采用或拨打确认。

15. **任务有效模型统一驱动准入与报价。** 有任务专属选择时，按当前任务选择或已恢复的任务配置解析有效模型；普通任务沿用既有全局来源。确认报价、积分准入与最终请求必须对应同一有效模型，不把任务选择写回全局，也不能因全局模型更贵误拦当前任务。目录失效、选择未就绪或准入失败保留真实错误；旧确认报价快照不可随余额或后续切模改写，实际执行仍通过后端校验。

16. **日志版本来自实际安装包。** 日志上传复用与版本展示 / 更新相同的平台安装版本来源，携带真实 versionName / versionCode；构建参数不等于同名 Dart 环境常量，不以默认 1.0.0（1）填充未知。读取失败保留原日志包并允许适用重试，不伪造版本或成功；账号切换及迟到回调不能将旧账号日志上传给新账号。后台按已上传事实展示，不猜测补版本、不改写历史记录。

17. **餐厅候选按搜索意图保持可拨打资格。** 普通附近、地区、菜系及品牌多门店候选只展示通过既有号码校验的门店，过滤发生在候选数量上限前；用户明确指定餐厅且真实相关命中唯一门店时，才保留该无号门店并在候选出现时说明暂无可拨打电话。不能仅因查询含品牌名或最终 limit=1 而启用无号例外，多家供选择时统一过滤无号。无号门店不进入拨号，不编造号码、不以其他门店代替指定目标；用户主动补号仍走原校验与确认。搜索、showOptions、实时和账本恢复保留同一候选身份、顺序和说明，客户端不复制筛选或重新排序。定位拒绝仍可指定城市/区域，授权后重搜沿用原 pending 生命周期；酒店及记忆采用、保存授权保持各自职责。

历史恢复清除旧进程的本地 overlay，再重建 durable 内容；这不等于授权删除已落账的开场、提示或正文。若实时已显示的必要业务内容未持久化，登记为恢复合同缺口，不能用恢复时重造本地卡片掩盖。纯查询状态不写入对话，不伪造已提交事实。

- Android / iOS 纯打包、必要检查、导出和明确授权安装，不新增任务、问题日志、OpenSpec、验证回执或仅记录打包的 Git 提交。正常工具输出与必要构建产物保留，源码版本、包信息、SHA256、环境 / 签名 / ABI / 配置和安装结果在对话中交付。
- 需要隔离打包时使用项目统一 run-test-build.py 调度，显式提供平台验证和产物导出要求，等待所有子进程结束。
- 只有构建、验证、全部导出完成且 SHA256 一致后，才能清理本次进程新建的临时空间；失败 / 中断保留，清理失败说明残留但不否定已验证交付。不得批量扫描删除历史或其他任务空间，常驻私有配置、签名材料与交付产物保留。
- 私有配置源不修改；先检查现有登记配置及忽略状态，再准备所需副本。工具自身生成的必要缓存不属于额外打包日志。

## 工具故障恢复

- 报错后重读当前进程 / 设备 / 页面状态，核对是否已执行及参数，再有限重试；默认一次，有新证据时再一次，不复用旧控件坐标或无限重复失败调用。
- 有副作用操作先查执行结果，不盲重放短信、认证、外呼、上传或收费，不通过卸载、清数据、扩大权限绕过问题。
- 单项工具失败时记录实际错误与未验证项，继续不依赖它的工作；平台终止轮次时不将仍运行的后台进程说成 agent 会自行继续。

## Android Debug 诊断读取

- 仅 Android Debug 在应用私有 readable-debug 子目录生成既有脱敏诊断的可读副本，保留原加密档案为唯一权威；副本沿用账号作用域、轮转、水位清理，失败不能阻断业务日志。Release / Profile 不生成可读副本，不为排查开启 debuggable 或扩大私有文件访问。
- Debug 读取命令与格式见 [本地诊断读取](docs/android-debug-diagnostics.md)。切换 Debug / Release 不修改权威档案格式，不因不能 run-as 自动清数据、卸载或换包。
