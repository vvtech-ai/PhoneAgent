Phone Agent Architecture

全栈架构与开源边界

从 Android 终端、托管后台，到 SIP/PSTN、远端模型、短信、地图、身份认证和存储平台，说明一次电话智能体任务如何流转，以及公开仓库实际开放了哪些部分。

Android：Kotlin + Jetpack Compose Backend：Spring Boot + Java HTTP / SSE / WebSocket SIP / RTP / WebRTC 文档基于当前代码核对

1. 全景架构

系统由开源 Android 终端、非开源托管后台和多个外部服务组成。终端负责用户交互与设备能力，后台负责账号、Agent、任务和电话编排，外部平台提供模型及通信基础设施。

2. Android 终端架构

终端不是模型密钥或 SIP 生产账号的持有者。它负责采集用户意图、获得确认、调用后台契约、承载实时媒体并展示结果。

UI Layer

  • Jetpack Compose 页面和导航
  • UiState / UiAction / UiEffect
  • 权限引导、任务确认和结果展示

Domain Layer

  • 任务、号码、联系人和回执规则
  • 通话、翻译、语音状态转换
  • UseCase / Coordinator / Policy

Data Layer

  • Retrofit HTTP API 与 SSE Agent 流
  • WebSocket 音频和实时事件
  • Repository、DTO、Mapper、本地缓存和日志

Integration Layer

  • 联系人、通话记录、相机、麦克风和 OTA
  • LiveKit、火山 RTC、SIP/WebRTC 音频
  • 随仓库提供的 CHAKEN 可信通信 SDK
终端通道主要用途安全边界
HTTPS / JSON登录、设置、任务、联系人、记录、OTA、日志上传使用账号访问令牌；服务端 Key 不下发
SSEAgent 增量回复、工具事件、任务进度和通话回执通过 sessionId/taskId/callId 关联
WebSocketASR/TTS、实时转写、通话监听/接管、翻译音频握手鉴权、时长和并发限制由后台控制
SIP / WebRTC / RTC终端侧拨号、媒体或实时语音能力依场景使用；生产账号与服务能力由后台租约/配置决定

3. 托管后台架构

当前实现是 Java/Spring Boot 服务，使用 Spring MVC、WebSocket、JPA、Redis、MySQL 驱动和 JAIN SIP 等组件。下列后台代码不随本开源仓库提供。

状态追踪：跨终端、Agent、SIP、模型和媒体桥的关键事件应携带 traceId、sessionId、taskId、callId、Provider 和状态变化，避免各模块维护互相竞争的事实源。

5. 核心业务链路

5.1 Agent 电话任务

1. 描述需求终端语音或文字输入
2. Agent 理解后台模型 + 内置 Skill/工具
3. 用户确认号码、时间、对象、内容
4. 电话执行SIP 账号池 + 实时模型
5. 结果回传SSE/HTTP → 转写、回执、记录

5.2 实时 AI 外呼媒体路径

后台编排器选择账号、路由和模型
SIP 平台信令注册与呼叫建立
PSTN 被叫真实手机或固话
媒体桥RTP ↔ PCM/Provider 音频
千问/豆包ASR、对话、TTS 或端到端语音

5.3 实时翻译电话

终端设置号码、语言、Provider、音色
后台建会话校验能力并分配 callId
SIP 媒体桥被叫 RTP 与翻译音频
翻译模型千问 LiveTranslate 或豆包 AST
终端呈现双方转写、译文、状态与控制

5.4 多路会议邀请

Agent 将联系人拆成独立呼叫任务，由后台在并发上限内为每一路租用 SIP 账号、创建模型会话并维护独立 callId。因此实际并发取决于：配置的 SIP 账号数量、线路是否允许并发/多设备注册、后台并发上限、模型并发额度和公网媒体可达性。

6. 数据、密钥与安全边界

终端可以保存

  • 登录会话和刷新所需令牌
  • 用户设置、模型/音色偏好和本地缓存
  • 用户授权的联系人和通话记录读取结果
  • 脱敏的客户端诊断日志

只能保存在后台

  • 模型 API Key / Secret
  • 短信 App Secret 与模板凭据
  • SIP 用户名、密码、号码池和路由
  • 高德 Web Service Key、数据库与对象存储 Secret

CHAKEN 可信通信 SDK 的客户端授权参数经明确授权可随开源终端分发，但写入 APK 的值均可被提取，因此它们必须是可撤销、最小权限且只适用于客户端的参数。它们不等同于后台生产密钥。

7. 本项目开源部分包括哪些

“Phone Agent 开源项目”在本仓库中专指 Android 终端及配套材料，不等于整个线上服务栈开源。

组件状态说明
Android 应用源码开源Kotlin、Jetpack Compose、AndroidX；UI、任务、网络、语音、通话、翻译、记录和设置逻辑
客户端测试与构建开源Gradle Wrapper、构建变体、单元测试、协议/策略测试和 GitHub CI
客户端通信实现开源HTTP、SSE、WebSocket、客户端 SIP/WebRTC/RTC 集成和 Android 平台适配
CHAKEN 可信通信 SDK授权分发公司自有且已加固的二进制随 app/libs/ 提供；适用其自身授权边界
项目文档与截图开源仓库包含README、构建、隐私、已知问题、架构、Call Skill 愿景和路线图
托管后台源码不开源Spring Boot 后台、Agent/Skill 编排、SIP 服务端媒体桥、管理后台和运维实现不在本仓库
数据库与部署材料不提供生产数据库、数据、后台部署拓扑、运行 Secret 和内部运维配置
生产服务账号与密钥不提供模型、短信、SIP、地图、对象存储、数据库和签名密钥
未获再分发授权的商业 SDK不包含例如声音克隆身份认证所需的部分商业 AAR/JAR，集成方需自行取得合法授权
Call Skill SDK / 市场规划中当前仅公开愿景和设计提案入口，尚无可执行的开发者 SDK 或分发平台

本仓库的 Apache-2.0 许可只适用于著作权人提供的终端源码，不自动授予托管服务、电话线路、短信额度、模型额度、域名、商标或第三方 SDK 的使用权。

8. Call Skill 在未来架构中的位置

Call Skill 计划位于用户意图与后台电话执行之间，把场景的输入、确认、对话策略、工具、权限和结果格式标准化。

用户意图“帮我预约…”
Skill 匹配场景与兼容性
输入与确认槽位、权限、风险
受约束执行对话策略与工具
结构化结果成功、失败、接管和回执

当前状态：开源终端并不包含 Call Skill 运行时。未来开放时，仍需要后台能力协商、安全审核、版本兼容和电话服务授权，不能仅靠一个 Skill 文件绕过真实外呼边界。

9. 典型部署视图

公网 Android 设备仅访问 HTTPS/WSS 与获授权媒体服务
DNS / TLS / 反向代理
应用区Spring Boot Backend
API/SSE/WS鉴权、限流、会话与业务接口
Agent/Call任务、Skill、SIP、媒体桥和回执
持久层MySQL、Redis、文件/S3
Secret 注入环境变量或受控 ConfigTree
受控出站网络 + SIP/RTP 入出站规则
供应商与公网电话网络模型、短信、地图、存储、SIP/PSTN

生产部署需同时验证 HTTPS/WSS、SIP 信令、RTP 端口/NAT、防火墙、账号注册并发和供应商额度。代码能证明对接方式，但不能替代 SIP 服务商侧路由授权、并发策略和公网放行检查。
