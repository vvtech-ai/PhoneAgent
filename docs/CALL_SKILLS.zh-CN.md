# Call Skill（通话技能）愿景

[English](CALL_SKILLS.en.md) | 简体中文

> 本文描述 Phone Agent 的公开演进方向。Call Skill SDK、运行时和分发平台当前尚未发布，文中的目录与接口均为概念示例。

## 为什么需要 Call Skill

不同电话场景有共同的骨架：理解用户目标、补齐必要信息、确认风险、执行通话、记录过程并返回结果。但餐厅预订、服务预约、售后沟通和会议通知所需的字段、话术、工具及完成条件并不相同。

Call Skill 希望把这些差异封装为可复用、可测试、可审查的能力单元，让开发者专注于场景本身，而不是重复搭建整条通信链路。

## 概念模型

一个 Call Skill 计划包含以下信息：

| 组成 | 作用 |
| --- | --- |
| 身份与版本 | Skill 名称、开发者、版本和兼容范围 |
| 匹配条件 | 识别哪些用户意图和场景 |
| 输入规范 | 需要收集的号码、时间、地点、人数等字段 |
| 确认规则 | 哪些字段或操作必须由用户显式确认 |
| 对话策略 | 通话目标、表达约束、澄清和失败处理方式 |
| 工具声明 | 可访问的地图、日历、订单或企业服务 |
| 完成条件 | 成功、部分完成、失败或需人工接管的判定 |
| 结果规范 | 返回给终端的结构化回执 |
| 权限与合规 | 联系人、位置、录音、区域和保留策略 |
| 测试样例 | 正常、拒绝、无应答、信息冲突等用例 |

## 设想中的生命周期

```text
发现用户意图
  → 匹配候选 Skill
  → 检查能力、版本与权限
  → 收集输入槽位
  → 向用户展示并确认任务
  → 创建受约束的通话会话
  → 处理对话、工具事件和异常
  → 验证完成条件
  → 返回结构化结果并留痕
```

## 概念目录

以下结构仅用于讨论，不代表最终规范：

```text
restaurant-booking/
  skill.yaml
  README.md
  prompts/
  policies/
  result-schema.json
  tests/
```

未来规范应支持版本校验、最小权限、确定性输入输出、脱敏日志、模拟测试，以及托管服务能力协商。

## 可以开发什么

- 餐厅、酒店和服务预约
- 会议邀请与出席确认
- 售后、维修和客服协调
- 快递、配送和上门时间沟通
- 航班、酒店、租车等出行确认
- 跨语言电话和无障碍辅助
- 企业内部通知与结构化回访
- 经授权的垂直行业工作流

场景是否能实际运行仍取决于电话线路、模型、区域、业务接口和合规许可。

## 安全底线

Call Skill 的设计必须优先考虑用户控制和通信安全：

- 发起真实电话前明确展示目标、对象和关键内容；
- 对号码、联系人、录音、位置等敏感能力采用最小权限；
- 对批量、多路或高频通话设置限额和二次确认；
- 提供拒接、无应答、对方质疑和人工接管策略；
- 不允许骚扰、垃圾营销、欺骗或未经授权的身份模拟；
- 日志和结果默认脱敏，并遵循数据保留策略；
- 遵守所在地法律、运营商规则和供应商条款。

## 开放路径

1. 公开概念模型、用例和 Skill 提案方式。
2. 设计 Manifest、输入槽位、结果和权限规范。
3. 发布示例 Skill、校验工具和模拟测试能力。
4. 开放开发者 SDK 与受控的本地调试流程。
5. 在安全和兼容机制成熟后探索社区目录与分发。

路线表示方向，不构成日期承诺。欢迎按照[贡献指南](../CONTRIBUTING.md)提交 Call Skill 场景提案、风险分析和测试用例。
